## Actual changes

1. The success InstallBudget HOSR revision validator is shared by decoder and encoder: `previous_revision=0` or a non-overflowing mismatch is `Error::InvalidField`; `previous_revision=u64::MAX` is `Error::IntegerOverflow`. No status or field numbers are changed.
2. Public allocation-free helpers `install_budget_request_id(u64)` and `install_budget_sequence(&[u8;16])` construct/extract the canonical little-endian low 8 bytes plus zero high 8 bytes, and reject sequence 0/max.
3. More negative tests cover QueryAbi feature/capability advertisement, maximum sizes, InstallBudget cap/period/revision/reserved, QueryDelivery terminal status/revision/object and historical request IDs, ReadUsage elapsed time/cumulative/event invariants, and RetireThrough forward bounds.
4. A **separately generated** x86_64 little-endian 32-byte ioctl transport descriptor fixture uses Python `struct.pack('<QQIIQ', ...)`, compared byte-for-byte against Rust `Transport` decode/encode in four new tests. The existing twelve 64-byte HOS2/HOSR golden frames are unchanged.
5. Deterministic test-only xorshift mutates the **12 independent fixed golden frames** for **49,152 attempted decoder inputs**, requiring any accepted variant to re-encode into identical bytes. Additional tests cover all eleven error statuses and HOSR parsing from copyout buffers with unused capacity.

## A03/A05 handoff

Production library remains the single `#![no_std]` dependency-free `hos2_os_abi` crate. Continue using `Transport::{decode,encode,ensure_success_response_capacity}`, `decode_request`, `encode_request`, `decode_response`, `encode_response`, `decode_response_for`, `decode_response_prefix_for`, `Opcode`, `Status`, and `Error`. The two new sequence helper functions avoid manually assembling InstallBudget IDs but **do not** assign sequences or implement CapSpace deduplication; those remain A03/A05 responsibilities.

The shared HOS2 version is still experimental major=2/minor=0. A published ioctl number has not been assigned; x86_64 little-endian remains the only documented first target; true permission/copyout/fault behavior and device execution are out of scope.
