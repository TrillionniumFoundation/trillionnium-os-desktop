## Caller-facing change

Previously, a caller could separately validate a transport and decode a valid
request snapshot without comparing `snapshot.len()` to `request_bytes` or
checking the opcode's success-response capacity before admission.

The dependency-free no_std crate now provides:

```rust
Transport::validate(&self) -> Result<(), Error>
Transport::decode_request_snapshot(&self, snapshot: &[u8]) -> Result<Request, Error>
```

The combined method revalidates public descriptor fields, checks exact snapshot
length, parses the frame and checks success capacity, in that order. A mismatch
between the descriptor and snapshot returns `InvalidTransport`. An owned
`Request` is returned; mutation or destruction of the input cannot change it.
This follows the existing NATIVE_ABI section 3 contract and changes no wire
field, version, opcode, status, permission or sequence rule.

Six new transport preflight tests cover all five operations, exact and short
capacities, public-field validation, mismatched snapshot lengths, address
overflow and exact arithmetic boundaries, malformed-input precedence, legal
overlap, and ownership after the input is overwritten and dropped. A runnable
rustdoc example also exercises the public method.

## Independent golden coverage

The new edge generator imports the existing independent Python frame packers;
there is still only one set of request/response header packing functions. Its
24 committed frames cover four nonterminal history states, all 11 saved
terminal rejection statuses, the final writable sequence (`u64::MAX-1`), a
successful revision increment to `u64::MAX`, matching saved installation
results, the nonzero history-reference upper boundary, a retirement frontier
whose next sequence is `u64::MAX`, and opaque read/history correlation IDs with
nonzero high bytes. No runtime sequence allocation or wraparound is implied.

Nine new Rust tests consume those exact hex bytes and assert typed semantics,
including correlation and the original over-cap statistics. They also reject
87 explicit invalid metadata/boundary variants. The ordinary Python ABI suite
now checks this generator and accepts its bytes using the existing independent
payload oracle. Existing HOS2 and transport fixtures remain unchanged.

## A05 integration boundary

Validate/decode the copied 32-byte descriptor **before** copying user input.
Copy the complete declared input once, then call `decode_request_snapshot`
before session authorization or reservation. The new helper never dereferences
addresses or performs that copy. User pointer access checks, faults, process
identity, CapSpace authority, delivery effects and copyout remain A05 duties.
This is an A02 interface handoff and host validation, not an implemented kernel
ioctl. HOS2 remains experimental 2.0; published ioctl numbering, other target
architectures and actual kernel/Hepta consumer integration remain open.
