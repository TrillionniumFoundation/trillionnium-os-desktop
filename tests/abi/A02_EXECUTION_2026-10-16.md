## Stable exported Rust interface for A03/A05

- No allocation or `std` dependency: `hos2_os_abi`, crate `libs/os-abi`, `#![no_std]`.
- `Transport::{new,decode,encode,ensure_success_response_capacity}`, plus
  `required_response_frame_len`, `Opcode`, `Status`, `Error`.
- `Request`/`Response`, `RequestPayload`/`ResponsePayload`,
  `decode_request`, `encode_request`, `decode_response`, `encode_response`.
- `decode_response_for`, `decode_response_prefix_for` and `declared_response_len`
  support trusted request correlation and buffers with unused output capacity.
- `Transport` now rejects arithmetic wrap of both pointer ranges, without
  substituting for kernel copyin/copyout, credential or canonical-pointer checks.
- Both successful and failed InstallBudget HOSR frames now validate the ordered,
  non-wrap sequence ID. Zero previous revision is invalid on success.

## Open boundaries

- ABI spec remains experimental and not stable; a unique published ioctl number
  and non-x86-64 transport validation remain outside this crate's guarantees.
- The current main contains host Rust A02/A03 implementations, not a verified
  HOS2 Asterinas kernel driver or native Hepta authority.
- Changes to shared HOS2 wire fields, persistence semantics, grants, or scheduler
  accounting must be escalated to A00 before any protocol modification.
