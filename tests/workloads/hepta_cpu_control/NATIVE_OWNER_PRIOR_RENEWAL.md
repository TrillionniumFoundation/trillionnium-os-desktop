# Continued original CPU control with a retained prior-boot Unknown

`run_native_owner_prior_renewal.py` separately enables
`prior-boot-unknown-renewal-v1`. It combines the original same-disk fault cut
with the original finite-owner renewal loop. The existing six ordinary
scenarios, finite prior-boot case, two activation cases and three genesis
cases remain twelve separate mandatory qualifications. Their exact event
keys, deadlines and success conditions are unchanged.

This additional case addresses a concrete failure: a historical old-boot
Unknown contributes one global drain blocker forever. Treating that count
as a prerequisite for every Stop prevents a successful original release and
causes Supervisor's stop timeout. A valid fix must retain that blocker and
the old K while allowing the original release transaction to decide the
current generation's actual responsibilities. This runner verifies the
result through real owners, physical materials and original journals.

## Original inputs and time bounds

The same source-review, original four-command owner build, original ELF
admission, exact-source OSDK build and G2 product kernel gates apply. The
compiled source pair and harness source are recorded separately. An older
host, kernel, ABI or native receipt cannot qualify a newer source pair.
The release profile, default features, 8 MiB ELF limit and 16 MiB LOAD limit
are unchanged. Loader byte-change and truncated-image negative controls are
actually executed before the campaign.

One 256 MiB raw ext2 disk is formatted once. Both actual QEMU processes
inherit the same exclusively held read/write descriptor through `pass_fds`;
the original drive opens `/proc/self/fd/<descriptor>`. Host device/inode,
filesystem UUID, size, link count and complete stopped hashes remain bound.
Forensic copies never become boot inputs. The existing QEMU machine, memory,
CPU, devices, network and boot flags remain unchanged.

The first boot retains its 120-second outer limit. Only this case's retained
second boot gets the existing 600-second renewal limit. Each Root session
remains 120 seconds, each original writer issue 20 seconds, each kernel
Manager grant 300 seconds, its Recovery grace 30 seconds and the independent
watchdog 5 seconds. The original fault callback still has at most two seconds.
No old issue is extended to make the campaign finish.

The plan contains only `schema_version`, `scenario` and a fresh `nonce`.
Actual persistent installation state determines fresh/retained phase; neither
the plan nor the runner supplies an authority, old boot, phase or Current.

## First boot and the durable old cut

The original writer admits one actual K/D and enters the original FileTransport
copyout-fault path. Root observes and durably saves its actual Current token,
complete head, independent material, issuer/key pin, clock/Registry and both
FinalUse frontiers. The host receives the matching `prior_boot_cut` line and
actually sends SIGKILL to that QEMU process group. Its raw return must be -9.

All serial bytes, including buffered bytes after the cut, are retained.
No later source terminal or other owner event is accepted. Host receive and
kill-call timestamps are recorded separately from the guest's emission and
callback BOOTTIME values. There is no verified mapping between those clocks:
`kill_within_guest_callback_window_proven` remains false.

Actual stopped live DB plus WAL and the independently retained material must
both match the source-defined complete logical anchor. All five original
lease/event/outbox/operation/dispatch-claim journals are read in that same
read-only SQLite transaction. They must contain the same old K, exact semantic
operation, immutable request, entered claim and Indeterminate event history,
with no terminal anywhere. This rejects a late kill even if an older archive
still contains Unknown. The first physical lease prefix is retained explicitly.

## Retained boot and finite original owners

The existing cold-open path must preserve the installation pin and key,
durable clock highwater, canonical issuer/proof, complete Registry retirement,
protected Current, exact physical material and consumer-local custody. The
new actual boot and kernel namespaces differ from the first boot. The initial
new Root lease uses its actual new boot/spawn ID; its observation binding
retains the original installation scope. These are distinct from the new
kernel effect namespaces.

The original device observer rejects the old D before selecting a new history
capability. It sends neither an old Install nor an old Query. The first
`prior_boot_observed` therefore records actual counts 0/0 and unchanged full
before/after retained operation. No arbitrary error or invented kernel Unknown
receipt can replace the original boot-mismatch refusal.

The original renewal routine then requires each actual Manager's prepared K,
native Applied receipt, durable source terminal, independent Current/material,
history ACK and a progressing CPU/heartbeat window of at least two periods.
Every Manager/Recovery handoff must produce the original successful release
receipt, Root-observed released Current/material and successful Supervisor
exit/reap. The restricted kernel launcher must produce at least two fresh
pairs. Complete raw launch and retirement receipts must match actual kernel
image/activation records and original durable Root observation files.

Acceptance requires a new Manager's actual Applied `effective_ns` to exceed
the second boot's first real Manager `sample_boottime_ns + 330_000_000_000` on
the same boot and stable CPU object. The original checked-add bound covers
both initial Manager and Recovery grants. Host elapsed time alone cannot
satisfy it. At most 64 actual Manager iterations are accepted.

Only this new case extends `continuity_owner` and `owner_released` with
`retained_prior_boot`. It has exactly `phase`, `observation`, `transport`, and
`terminal_lookup`. The terminal accessor must return the original typed
`illegal_transition` branch with reason
`HOS2 predecessor lacks complete durable native terminal evidence`; another
error is a failure. Each actual Host's startup snapshot contains the old K,
and that K's complete before/after semantic operation and request remain
identical. Its global drain count remains one.

Manager descriptor counts are 0/0 at start and 1/1 before Stop, accounting
for that Manager's one independent new effect. Recovery counts remain 0/0.
Every old observation leaves those actual counts unchanged. A cumulative new
Install count is never labeled an old-D count. `owner_released` samples its
old-K observation before Stop; it does not claim to query a closed Host.

After the renewal endpoint, the final `prior_boot_observed` includes the
actual original Root authority observation. The original final release/reap
and `complete` follow, then sync/reboot must produce actual QEMU raw exit 33.
The completion token names the last effect's terminal Current. The separate,
later released Current is the final physical cut; these receipts are never
substituted for each other.

## Independent physical checks

Every actual `owner_released` material is opened by its exact Current-derived
path and actual observed SHA. Its full source-defined logical anchor and
complete journal prefix are checked. The final active database and actual WAL
must match the final released material. No `immutable=1`, checkpoint, repair,
ledger write or source-created fixture is used by the reader.

The old lease and old operation have different semantics. The first stopped
lease is one exact Active row; original cold recovery must append its same
generation/binding RolledBack expiry before acquiring the next generation.
That lease expiry must not create an operation terminal. Each new owner must
have exactly Active → Released rows with contiguous generations, distinct
active fencing tokens and an actual observed released lease-head digest.
Each new Manager has its exact admitted/indeterminate/reconcile_committed
chain and actual native terminal; Recovery performs no new effect. The old
K's complete events, immutable admission/outbox/operation and entered claims
remain byte-for-byte unchanged throughout every retained prefix.

The Root observation directory has one exact joint inventory: the immutable
first cut, the actual second-boot launch observations and their original
locks. Arbitrary extra files or unfinished `.next` records are rejected.
Original genesis, fixed sequence-one proof, first activation and all recovered
activation witnesses are independently checked; the original immutable
records and installation pin retain their bytes and inodes across boots.

The original FinalUse state/directory/lock custody and old claim prefix are
preserved. Device has exactly one old claim plus one for each actual new
Manager effect; Notes has none. The actual local journals, protected Root
frontiers and owner observations must agree. No arbitrary observation file
or reset claim store is accepted.

## Explicit invocation

Run only after the final reviewed original owner and matching product kernel
have actually passed their build/input gates. All paths below are explicit
inputs; hash arguments refer to the retained actual files, not old receipts.
`--kernel-pipeline` is the directory containing `pipeline.json`.

```bash
python3 tests/workloads/hepta_cpu_control/run_native_owner_prior_renewal.py \
  --execute \
  --desktop-source /absolute/frozen-os-source \
  --hepta-source /absolute/frozen-hepta-source \
  --source-review /absolute/source-review.json \
  --expected-source-review-sha256 ACTUAL_REVIEW_SHA256 \
  --owner-elf /absolute/original-owner.elf \
  --owner-build-receipt /absolute/original-build/result.json \
  --expected-owner-build-receipt-sha256 ACTUAL_BUILD_RESULT_SHA256 \
  --kernel-pipeline /absolute/product-kernel-evidence \
  --expected-kernel-pipeline-sha256 ACTUAL_PIPELINE_JSON_SHA256 \
  --qemu /absolute/qemu-system-x86_64 \
  --expected-qemu-sha256 ACTUAL_QEMU_SHA256 \
  --bios /absolute/bios-256k.bin \
  --mkfs /absolute/mkfs.ext2 \
  --debugfs /absolute/debugfs \
  --first-timeout 120 --timeout 600 \
  --output /absolute/new-evidence-directory
```

The new output retains both `boot-*/qemu.json`, raw `serial.log`, stopped
state copies, input/source/harness inventories, exact source schema, tool
identities, every read-only extraction command and every SQLite query.
`boot-*/physical/result.json` contains the independent physical checks;
`boot-2/physical/released-material-*` retains each actual release prefix.
The original execution input remains `campaign/state.raw`.

The five new host modules are `test_native_owner_prior_renewal_sql`,
`_store`, `_files`, `_evidence`, and `_runner`. Their explicitly inert records
exercise parsers and real private ext2/SQLite/WAL I/O. They never qualify
Hepta execution. Run them with `python3 -B -m unittest -v` and their full module
names from this directory, followed by the unchanged fifteen-module original
116-test command. The frozen delivery manifest records exact commands and
actual counts; development failures/earlier records remain separate.

Success establishes this bounded two-boot, Unknown-preserving renewal case.
It leaves `power_loss_verified`, `unbounded_persistent_cpu_verified`,
`g2_complete`, and `production_ready` false. Source review, host tests, ABI
probes, kernel tests and successful compilation cannot set native acceptance.
