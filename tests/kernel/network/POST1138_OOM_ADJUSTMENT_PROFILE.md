# OOM adjustment source profile

`post-1138-oom-adjustment-v2` is a new exact-byte admission profile. Its 182
explicit roles inherit
the 132 role/path identities of frozen e7ed's narrow Unix STREAM profile,
records the changed clone dependency explicitly, and binds OOM implementation,
native fixtures, credentials, proc DAC, VM publication, lifecycle and new owned
guest QA dependencies. It keeps the original historical engine and Unix
protocol/oracle bytes unchanged. Source admission alone does not qualify an ELF.

The old signal wrapper still owns its original 132 literal hashes and cannot
admit the new runtime. Its positive source-admission tests now use the exact
frozen e7ed Git blobs, verified in memory by compressed SHA, Git blob, role and
content SHA. This follows the existing cpunode/retirement historical fixture
pattern. Those tests preserve the historical contract; they are not rerun
qualification of the current product. The new profile independently requires
the current regular source bytes and rejects old profile names for those bytes.

Whole-tree clean-head admission, source-before/after equality, original native
and ordinary guest wrappers, and source/ELF/log identities are still required.
Historical mutation variants cannot use the new profile. Source drift, missing
roles, duplicate paths/roles and an altered private engine are rejected. No
operator-supplied manifest or hash list can substitute for the literal profile.

The first `07bff624` host-network run actually executed 84 tests and returned
one error: the aggregate current-source test still passed new clone bytes to
the old signal profile. That failed run, original driver/receipt and full source
snapshots remain retained separately. This QA-only v2 fixes that import, keeps
the aggregate test's exact old-signal clone-mismatch rejection, and explicitly
binds the aggregate test as role 182. It rejects the unqualified OOM v1 profile
name. No old literal, historical fixture, kernel code or native test changes.
The new v2 host, native and ordinary guest qualification remain unrun at this
source revision; the retained v1 failure is not reclassified as success.

The narrow Unix transport boundary is unchanged: only Unix SOCK_STREAM uses
the aggregated writev dispatch. TCP/UDP/VSOCK retain the b446 transport path.
The OOM stage does not enable memory.max, broaden Hepta authority, or qualify
the combined CLONE_THREAD|CLONE_VFORK mode.
