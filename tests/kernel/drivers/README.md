# Source-bound virtual display, input and block devices

This separate gate executes the original Asterinas drivers in two disposable
QEMU boots. It does not qualify physical hardware, a native GUI application,
GPU acceleration, production Root authority, full F1/G2 or power loss.

`native_devices.c` is a static guest-only probe. Its first action verifies a
fresh nonce in the guest kernel command line before any mount or display write.
The host never executes it. Missing framebuffer, evdev or block devices fail;
the upstream device tests' optional-device skip is not accepted here.

| Module | Responsibility |
| --- | --- |
| `run_native_devices.py` | Admit the retained ordinary source-built kernel and exact source snapshots; compile the tracked probe; format one new 64 MiB ext2 image; create two GRUB boot images; retain the actual QEMU child, QMP peer PID, commands, pixels, serial and state hashes. |
| `native_devices.c` | Open the actual named virtio keyboard and query its ID/capabilities; paint/read the actual fb0 mapping; write/fsync/read or reopen the original ext2 inode; read one actual key press/release from evdev. |
| `native_devices.py` | Reject missing/replayed/reordered records, wrong identities and payloads; compare every actual PPM pixel with the guest's four-band framebuffer; require the original stored inode/payload after a second boot. |
| `test_native_devices.py` | Inert parser and image-corruption regressions. These are not native execution evidence. |

## Build inputs

First execute the original current-source
[`build_kernel.py`](../../workloads/hepta_agentd_runtime/build_kernel.py).
The new gate requires its actual successful ordinary kernel/boot/QueryAbi
receipt and its independently retained digest. The kernel, initramfs and
SeaBIOS bytes come from that receipt directory. Kernel and harness checkouts
are separate explicit clean Git identities; complete snapshots are retained
and compared after execution. An old kernel is not relabelled by a new harness.

The ordinary receipt freezes OSDK's QEMU-direct ELF64 with its documented
`make_elf_for_qemu` conversion to `EM_386`. GRUB requires `EM_X86_64` instead.
The controller creates a separate loader image by restoring only bytes 18–19
to `3e00`; it retains both SHA256 values and never modifies the frozen input.
The entry, program headers, every LOAD segment and all other bytes remain
identical. Thus this gate runs the same compiled kernel code through GRUB's
display-capable loader, with an explicitly different ELF machine header.

The controller needs actual GCC, GRUB's `grub-mkrescue` and its xorriso helper,
an ext2 formatter, and QEMU. Tool paths/hashes and compiler/formatter/ISO
commands are retained. No original executable or kernel is downloaded or
generated by the evidence parser. Supply canonical paths and a new private
output directory outside both source trees and the retained kernel inputs.
The optional `--xorriso /absolute/helper` selects a private helper explicitly;
retain its package/library hashes alongside the execution record when it wraps
locally extracted packages. It does not require a system installation.
`--grub-directory /absolute/i386-pc` selects BIOS platform modules when the
host only has EFI modules. Every selected platform file is hashed before and
after the two boots; no EFI/mtools fallback is used for this SeaBIOS profile.

```sh
python3 -I -B tests/kernel/drivers/run_native_devices.py --execute \
  --source-root /absolute/compiled-desktop \
  --expected-harness-head FULL_HARNESS_HEAD \
  --expected-harness-tree FULL_HARNESS_TREE \
  --kernel-inputs /absolute/current-kernel-build \
  --expected-kernel-receipt-sha256 FULL_KERNEL_RECEIPT_SHA256 \
  --qemu /usr/bin/qemu-system-x86_64 \
  --expected-qemu-sha256 FULL_QEMU_SHA256 \
  --output /absolute/new-device-evidence
```

Without `--execute`, the runner performs no inspection, formatting, compiler
or guest operation. The uppercase placeholders cannot pass admission.

## Actual execution contract

Each boot uses q35/TCG/max, one vCPU and 512 MiB, no network and no host disk.
The block device explicitly uses the supported modern virtio PCI transport at
00:08.0 (legacy disabled), matching the original native-owner device profile.
The VGA/GRUB path explicitly selects 1024 by 768 pixels. The original kernel
executes its fb0 and virtio input/block implementations; this is a
different declared device profile from the headless N0 test profile.

Before sending input, the controller connects only to its retained QEMU PID's
private QMP socket and captures its actual display. Every PPM pixel must show
the original four bands that the guest wrote through fb0. A mapped buffer,
single colored point, file existence or serial success marker is insufficient.
The controller then sends exactly one virtual `a` key. The named evdev device
must deliver one `KEY_A` press and release through the real kernel input path.

The first boot creates one 4096-byte file with `O_EXCL`, fsyncs the file and its
parent, and reads the exact nonce-derived content. After unmount and ordinary
guest shutdown, the second boot receives the same retained raw disk, opens the
original file without create/write flags, and compares its inode, device,
length and complete contents. Both boots must exit through the original
successful shutdown with raw QEMU exit 33; any timeout or panic fails. The
default budget is 90 seconds per boot and cannot exceed 120 seconds.

This is clean guest reboot persistence. It does not claim abrupt power loss,
storage-controller reset, a Root/Host writer crash, IME, accessibility, or a
physical keyboard/display result. Keep those independent product gates.
