# 架构决策记录

版本：0.1。日期：2026-10-16。决策是开发方向，不是实现证明。

## D01：新仓库而非旧桌面改造

已确定。使用删除后同名重建的仓库，初始历史只包含本次空 README 和新文档。不继承旧代码、旧 PR、旧工作流或旧完成度。根 README 保持零字节，开发入口为 docs/INDEX.md。

## D02：Hepta 为原生智能控制平面

已确定。复用 hepta-private-ci 现有模型与工具执行主链，以窄的资源/设备适配器接入 OS。拒绝第二套 Agent/权限/操作数据库。当前上游固定为 f8c9419df6ddeb36ff8b522a50219981fb8d9345。[来源](SOURCES.md#hepta-architecture)

## D03：Rust 内核与用户态智能分离

已确定。内核负责机制、隔离和快速路径；Hepta 在用户态负责策略和任务语义。必要的汇编/unsafe/FFI 显式记录。拒绝把模型、数据库和远程控制放进中断或线程切换路径。

## D04：优先评估 Asterinas/OSTD

暂定基础选型，M0 必须用实际构建和最小差异确认。复用 Rust 底层与兼容实现可减少重复基础工作；并不因此声称本项目已经获得上游全部能力。暂不并行维持“完全从零”和“完整 Fork”两套产品主线。[来源](SOURCES.md#asterinas)

重议条件：核心资源/能力模型无法在可控修改范围内实现，或实测隔离/兼容代价与目标显著冲突。重议必须提供具体失败与修改成本，而不是只因追求架构标签。

## D05：Linux ABI 原生兼容为主

已确定。未修改 ELF + 固定用户态依赖 + 行为差分。VM 为明确标记的补缺，不是偷换最终目标。用户态 ABI、内核模块、设备接口与指令集分开验收。[来源](SOURCES.md#linux-abi) [来源](SOURCES.md#starnix)

## D06：保留 AOSP 用户态

已确定的初期路线。先适配内核/Binder/HAL，不同时重写 Framework/ART。精确 AOSP 构建版本、设备类型和翻译器尚待选择。认证和第三方服务器策略不算作单纯内核兼容问题。[来源](SOURCES.md#aosp) [来源](SOURCES.md#play-integrity)

## D07：先通用资源，不做模型专用内核

已确定。任务、内存、队列、设备能力是 OS 对象；具体模型 KV、分块和推理调度语义留在推理模块。接口尽量随着模型变化保持稳定。

## D08：先 CPU 垂直闭环，再扩大设备与本地模型

已确定的开发顺序。第一闭环必须包含真实 Hepta、真实新内核、预算生效和故障恢复，不等 GPU 完成才验证核心价值。之后必须单独完成实际本地计算，不长期用云端或 Linux 宿主冒充原生推理。

## D09：默认可靠回退，不强迫全部使用 AI

已确定。AI 服务不可用时采用固定策略和本地恢复。性能必须与无 AI 对照比较；收益未经实测时不宣称更快。Linux sched_ext 的错误恢复可作设计参照，但不是最终 Rust 内核实现。[来源](SOURCES.md#sched-ext)

## D10：只增加实际必要的检查

已确定。保留内存/能力隔离、资源上限、实际结果核对、数据恢复与回退。普通代码和文档开发不新增形式主义审批、多重签名、重复注册表或无意义 CI 队列。具体测试跟随改动，失败定位到实际代码和环境。
