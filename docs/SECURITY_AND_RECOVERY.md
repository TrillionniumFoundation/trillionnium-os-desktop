# 安全、故障与恢复

版本：0.1。状态：待实现要求，不是安全认证或形式化证明。

## 1. 信任模型

用户程序、APK、兼容层输入、模型输出、检索内容和远程任务都不能直接成为内核权限。Hepta 对用户目标的解释可以不确定；页表隔离、句柄检查、设备映射、资源上限和停止行为必须确定。

内核与特权底层属于受信任计算基础。若兼容层或驱动运行在内核地址空间，它们的逻辑错误可能影响整个系统；safe Rust 不消除这个事实。设备固件、DMA、FFI 和 unsafe 的边界需要分别检查。

Hepta 原架构明确把权限、硬约束、状态所有权与学习过程分离。新 OS 延续这一职责，不复制另一套智能权限体系。[来源](SOURCES.md#hepta-architecture)

## 2. 主要攻击面与故障

| 场景 | 必须执行的机制 | 反向测试 |
| --- | --- | --- |
| 模型或文档诱导扩大权限 | 请求只使用已有内核能力，模型不持根权限 | 未授权设备、跨工作区访问被拒绝 |
| 参数校验后变化 | 内核复制不可变控制描述符后核验 | 并发修改用户缓冲区 |
| PID/句柄/队列重用 | boot identity + generation + 实际调用身份 | 重启、关闭重开、设备复位后的旧请求 |
| DMA 越界或悬挂 | 受限映射、固定页、完成/排空/复位后回收 | 越界、设备超时、进程退出 |
| 资源耗尽 | 域级预算、队列上限、恢复资源预留 | CPU 饥饿、内存耗尽、fd/队列洪泛 |
| Hepta/模型失效 | 内核固定策略与独立恢复服务 | kill、网络隔离、模型加载失败 |
| 操作结果丢失 | 保留 unknown、由原操作所有者核对 | 提交后断连、重启、重复请求 |
| 更新失败 | 可恢复前驱镜像与兼容状态 | 启动失败、迁移失败、断电 |

未实现相应机制前，该范围不能宣称安全支持。

## 3. 必须保持的快速路径

中断、调度、缺页、撤销检查及设备停止不得依赖模型、远程 RPC、区块链、通用数据库或复杂证据汇总。使用内核拥有的当前策略和撤销代际做本地检查。

学习可以提出新策略或源码候选，不能直接在线重写活跃页表管理、权限签发规则和设备安全边界。新策略有固定范围、版本与回退行为；数据中心或 Fleet 故障不能阻止本机恢复。

## 4. 能力撤销与在途工作

撤销分为阻止未来使用、排空已提交工作和实际终止三件事。对不可取消的硬件操作，等待真实完成或进入明确的未知状态；不能为了显示“已取消”而释放仍被 DMA 使用的内存。

对没有可靠复位/隔离机制的设备，明确限制共享与恢复承诺。IOMMU 与设备分组是隔离条件的一部分，不是仅有一个配置选项就算完成。[参考](SOURCES.md#vfio)

能力租约失效应撤回管理权并恢复预定义安全资源策略，不自动杀死独立应用。哪些资源必须立即关闭（例如已撤销麦克风会话）由操作契约规定，不能用一种统一回退覆盖所有设备。

## 5. 持久化与重启

内核瞬时身份不跨启动复用。重启后旧句柄和队列能力全部失效，原 Hepta 操作所有者使用新启动身份核对未完成操作。未知结果不会被自动转换为失败并重试。

必要文件系统持久化需要明确 flush、写回、日志/事务与恢复顺序。崩溃转储和诊断日志有大小限制及隐私过滤；不能为了保留所有日志耗尽恢复分区。

第一版恢复顺序：基础内核与安全配置 -> 存储一致性 -> 本地恢复服务 -> 权限与撤销状态 -> Hepta 原领域状态 -> 运行时 -> 新操作。内核基础启动不等待后面的智能组件。

## 6. 更新与回滚

先支持离线重启式内核更新，不把热替换内核作为初期要求。构建产物、配置与依赖有明确内容身份；可启动前驱与恢复入口独立于新 Hepta 版本。

状态 schema 升级不得只回退二进制而保留不兼容状态。回滚不得复活已经撤销的权限；需要单独维护兼容的撤销前沿或拒绝回到无法解释该状态的旧版本。将这项实际机制实现为小范围代码，不另建层层审批平台。

本机所有者决定更新授权，已授权维护可以自动执行；并不要求每个 commit 都新增人工批准。真实设备覆盖、内核权限变化和数据破坏风险的验证不能用“自用”取消。

## 7. 恢复交互与用户数据

用户始终有不依赖 AI 的停止、关机和恢复入口。原生桌面可以重启，但可信恢复入口和权限提示不能由任意应用伪造。

跨工作区屏幕、剪贴板、文件和输入共享需明确能力；一般日志不记录密钥、令牌和用户内容。测试数据优先使用合成样本，不把现役业务数据复制进公开仓库。

## 8. 发布阻断问题

内核 panic、越权访问、数据损坏、旧句柄重新有效、DMA 页提前释放、无法停止的资源耗尽，以及把未知硬件结果误报成功，均阻断对应功能发布。其他功能缺失可标为不支持并继续开发，不因一个未涉及设备阻止所有工作。
