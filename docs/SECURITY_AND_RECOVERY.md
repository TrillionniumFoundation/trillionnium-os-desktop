# 安全、时间与恢复契约

版本0.3。权限/状态机以 [NATIVE_ABI](NATIVE_ABI.md) 为准，实际状态以 [STATUS](STATUS.md) 为准。

## 1. TCB 与统一边界

内核、特权底层、内核态驱动及受限执行桥分别列为受信任组件。safe Rust 不证明逻辑授权、DMA协议或故障隔离；同地址空间的兼容层 bug 仍可能影响全内核。模型输出、网页、APK、远程任务和请求体不成为权限。

所有ABI/设备别名最终查同一对象策略。域内root、capabilities、Android UID/Binder/MAC不得升级为机器所有者。原生控制fd绑定真实打开进程的CapSpace，不能靠传fd或PID重用继承权力。读取/调试受限桥必须受域/身份策略保护，否则“无权模型、强权桥”的隔离无效。

## 2. 启动、准入与撤销

NATIVE_ABI规定先完成最终exec身份，再由可信启动器ActivateGrant；普通exec仍撤旧权限。先在CapSpace投递窗口预约唯一D，后在资源锁内检查当前grant/期限/revision并提交效果与终局。跨目标不能只靠各自资源锁去重；预约和结果容量都必须先于效果。

grant关闭/撤销与准入使用同一对象同步域；强引用不延长授权。旧桥被fence以后才允许新桥激活，保留旧未决K，不能将进程退出直接解释为没有效果。历史观察通过独立DeliveryView，不忽略revoked来模拟观察权。

## 3. 取消与资源回收

execution、cancel、effect、observation分别记录。停止设备不是零效果。设备已确认quiesced且所有CPU引用退出才能回收DMA页；effect仍unknown时可保留小型语义tombstone而释放安全可释放的大缓冲。缺乏静止证明时有界隔离设备/队列，不能为了省内存冒险释放，也不能无限创建未决队列。

独立OS恢复职责使用基础init/监督进程及其内部受限接口，必须有不可被目标域/祖先削减的CPU、内存、必要I/O与timer唤醒。不能把Hepta的runtime.supervisor当作唯一恢复基础。管理者进程退出或内核租约到期均可触发恢复；心跳文本不是进程可运行证明。

| 可信原因 | 回退动作 |
| --- | --- |
| 用户明确暂停 | 保持暂停；另行授权恢复前不因桥退出自动解除 |
| 管理租约失效/桥退出 | 撤销manage，恢复启动配置中的保守cap，受当前父域/安全上限约束 |
| 模型不可用但管理租约有效 | 不再采用新AI提案，保持仍合法的已验证策略或启动配置指定固定策略 |
| 紧急压力 | 基础恢复执行者使用确定性限额，不能扩大旧权限 |
| 摄像头/麦克风等设备撤销 | 按设备独立停止/排空规则，不套用CPU策略 |

初版暂停原因与恢复策略来自可信启动/维护记录；InstallBudget只含cap，不足以表达用户暂停。内部RevokeGrant/ApplyRecovery接受实际对象、预期grant epoch、可信原因和当前启动身份；在对应对象锁检查和执行，回执区分新准入关闭、策略生效与硬件静止。没有这些内部实现前，revoke/kill闭环仍未完成。实际恢复时延须测量，不凭配置声明硬实时。

## 4. 熵、时钟、boot identity

使用上游CSPRNG与已支持的可信熵来源，记录virtio-rng/硬件熵配置及失败模式。熵未就绪时允许无网络诊断启动，但不签发可用于外部认证的秘密、TLS凭据或授权session；返回明确不可用，不使用固定种子装作安全随机。

boot_id、CapSpace ID来自已就绪CSPRNG，非零且不从PID/墙钟推导。确定性QEMU测试种子只用于synthetic profile；N0不支持带活动授权的快照恢复/克隆或宿主休眠恢复；在可信before-resume失效流程实现前，禁止将这些场景算作支持。仅重新生成随机数不能证明旧投递/撤销状态不会复活。

租约与策略时限用内核初始时钟域（不随Linux time namespace偏移）的CLOCK_BOOTTIME等价单调时间，预算CPU用量由实际运行计数累计。墙上时钟用于日志与必要证书时间校验，不决定本地授权剩余时间。重启后旧lease/CapSpace无效；不能把过去boot的数值期限直接搬到新boot。缺可信墙钟时拒绝需要正确证书时间的连接，不关闭证书检查。

## 5. 选定存储路线与资格范围

S0开发输送允许只读initramfs或固定上游NixOS镜像；host-backed/virtio-fs仅用于开发数据路径，其成功不证明本系统块设备耐久。S1原生耐久候选固定为virtio-blk + 上游Ext2路径，CPU架构/缓存/flush配置锁定后运行真实锁、短写、WAL、目录fsync和恢复测试；Ext2本身不被描述为日志文件系统。未通过S1前只使用可丢弃合成数据，不部署真实Hepta可写业务状态。

若上游Ext2无法满足所需fsync/目录/崩溃语义，保留最小复现并修复该路径或作单一文件系统选型变更；不同时开启多个永久存储后端。具体镜像与配置hash仍需构建时补齐，不能以这个设计选择宣称持久化通过。

Hepta原SQLite/操作journal拥有业务提交事实；文件系统fsck与数据库完整性各自检查。写满、EIO、短写、rename及flush前后失败，不得静默截断账本或将未知操作改为失败后重试。[SQLite原子提交](SOURCES.md#sqlite)

## 6. 更新状态机

使用离线重启更新：downloaded -> verified -> staged -> trial_boot -> confirmed；失败到 recovery/previous_compatible。镜像与可写状态分离，至少保留一份已知可启动前驱和不依赖新Hepta的恢复入口。trial次数有界（初始试验为2次），启动计数持久化失败则进入恢复，不无限重启。

verified包含内容hash和受信任来源验证；hash不证明谁发布了文件。binary、schema、权限/撤销前沿作为兼容组合选择，旧系统不能解释新撤销状态时禁止回滚到该组合。需要兼容快照时只包含可恢复的授权状态，不使已经删除的数据或撤销权限从旧备份复活。

初期不是热补丁内核。更新授权可以在所有者明确范围内自动执行，构建测试不增加额外审批服务。真实硬件部署另做明确执行任务，本轮不更改现役内核。

## 7. 故障模型

应用kill、客体内核reset、VMM退出、丢弃易失缓存、受控短写/乱序、真实断电分别记录。杀QEMU后宿主缓存可能继续写盘，不能以此证明掉电耐久。选中故障层级、破坏窗口、预期不变量后再执行。

操作重启核对必须使用原K；查询不存在、不再拥有执行权、静止确认、效果未知都是独立事实。日志有配额并过滤用户数据/密钥，容量不足拒绝新效果但保留停止/恢复能力。

## 8. 负面用例

ABI别名绕过、fd跨进程、fork/exec、stale generation、授权与提交竞争、桥越权、partial write后取消、重复K变内容、copyout失败、额度刷新与迁移、共享页泄漏、未就绪熵源、墙钟回退、快照克隆、状态不兼容回滚、UI/模型/网络失效。规格模型不替代上述实机或内核故障注入。

## 9. 共享计费和桌面恢复的范围

进程退出可释放CapSpace，计费对象在共享页/缓存仍被引用时转为禁止新分配的残留对象；待最后引用释放后销毁，残留数量与元数据有界。跨域共享在建立时决定额度与回收责任，杀死已退出的首次分配者不能释放其他进程持有的页。此为未来内存控制要求，不宣告本版CPUwire已实施。

聊天shell、compositor/session和GPU为不同故障域。shell可与连接所有者分离重启；compositor连接丢失和GPU reset不能承诺所有旧应用无损恢复，必须分别验证。
