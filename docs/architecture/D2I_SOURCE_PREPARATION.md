# D2I deterministic runtime source preparation

## Status and authority boundary

This document governs the source-to-source transformation performed by
`tools/prepare_d2i_runtime.py`. A successful transformation establishes only
that the tracked runtime has the reviewed, unambiguous source shape and that
its generated bytes are reproducible. It does not establish Rust compilation,
Servo execution, a rendered frame, product BrowserActor dispatch, installed
Debian/QEMU behavior, hardware, signing, publication or release readiness.

The transformer neither changes Git refs nor promotes project state. Its
transformation receipt is not a runtime or image qualification receipt.

## Inputs and outputs

The caller supplies three explicit paths:

```text
--source    runtime/servo/hepta_workspace_runtime.rs
--output    <qualification-output-directory>/runtime.rs
--evidence  <qualification-output-directory>/transformation.json
```

The source must belong to the exact tested checkout. Output paths must be in a
private qualification workspace, not a tracked source file or a production
installation. The caller retains responsibility for workspace/path custody,
exact commit and tree identity, source and toolchain locks, and preserving the
transformer's nonzero exit status. This tool is not a filesystem sandbox.

The transformation receipt binds the source and generated UTF-8 bytes by
SHA-256. Its fixed status is `PASS_DETERMINISTIC_REVIEWED_TRANSFORMATION`.
The callback-independent crash requirements remain unchanged: a zero-process
intermediate state, distinct replacement identity and external-navigation
refusal are required. The downstream Rust, headed-runtime and image gates
remain independently mandatory.

## Exact-anchor protocol

Every literal or regular-expression anchor must have exactly one match in the
current intermediate source, before replacement. Empty anchors and zero,
two or more matches are errors. Regular expressions retain DOTALL and normal
replacement/backreference semantics; literals are not interpreted as regexes.

Counting substitutions after limiting replacement to one is insufficient: it
would report one replacement even when the source contains multiple anchors.
The transformer therefore counts all matches first and only then performs the
single reviewed replacement. It does not choose the first ambiguous location,
skip a missing transformation, normalize an unknown source shape or replace a
runtime with a fixture to obtain a passing result.

Transformations are applied in their reviewed order. Altering an upstream
anchor or the pinned runtime requires updating its transformation and tests in
the same bounded change, followed by exact-object requalification.

## Failure and persistence semantics

All anchor checks complete in memory before either generated output is opened
for writing. A source-read, missing-anchor or ambiguous-anchor failure returns
nonzero and creates no success output. Existing artifacts from an earlier run
are not made current by a failed invocation and must never be accepted after
its nonzero exit. A caller must stop rather than fall back to those artifacts.

The two output writes are not a transactional pair. An I/O failure can leave a
partial output or one of the two files. Downstream consumers must require a
successful invocation, verify the exact source/output digests, and use a fresh
private qualification directory. File existence alone is not success.

## Executable validation

Run the actual preparation and boundary corpus with:

```bash
python3 -m unittest tests.test_d2i_runtime_preparation -v
python3 -m unittest discover -s tests/d1 -p 'test_*.py' -v
```

The new corpus executes the transformer in isolated temporary output
directories against the tracked Servo runtime. It checks deterministic bytes,
receipt digests, preservation of source bytes, required claim boundaries,
missing and duplicate source anchors, no success output on rejection, and
preservation of previous output on pre-publication failure. Helper tests cover
literal and regex cardinality, multiline matching, backreferences and empty
patterns. These tests generate source only; they do not start Servo or QEMU.

The existing S10 source-contract job discovers `tests/test_*.py` for both the
exact head and prospective merge before its expensive image jobs. Thus this
executable preparation check is exercised early without changing or removing
any later build, crash, installed-image or independent review requirement.

## Change and evidence protocol

Changes to runtime source, transformation, regression corpus, workflow,
compiler, Servo pin or image inputs invalidate their corresponding evidence.
Bind diagnostics to the exact commit, tree, source blob and generated digest.
If a log reports a source marker absent from those bound bytes, classify the
failure diagnosis as unresolved until the source identity is established;
do not modify another revision or transfer a historical pass.

A passing source-preparation test may close only its bounded source defect.
It cannot close S08, S10, D2I, governance, hardware or release gates.
