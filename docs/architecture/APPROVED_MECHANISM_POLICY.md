# Rooted approved mechanism configuration source boundary

This additive Linux source path loads explicit reviewed issuer configuration and compares actual live Control and Agent identities against it. It does not install configuration, start the product broker or authorize TaskFlow actions. The main binaries remain unavailable/disabled by default. The closed inventory is `contracts/approved-mechanism-policy.v1.json`.

`ApprovedPolicyDocument::open_default_before` reads only `/etc/hepta/approved-mechanisms.v1.conf`; an absent or empty file refuses. The explicit-path constructor has the same custody rules and creates nothing. Approved pins, IDs, unit, cgroup and role tags come from the file. No PID, procfs snapshot, environment, NSS result, caller boolean or currently observed executable becomes approved configuration. Local UID0 in the loader's selected user/mount namespace does not establish host production-root authority. Production issuance, deployment, account mapping and host namespace assurance remain external requirements.

The versioned ASCII file has exactly 13 fields: schema plus each role's uid, gid, unit, cgroup, elf_sha256 and principal_id. The contract fixes byte/path bounds and grammar. Integers have canonical decimal syntax, hashes lowercase hex, units exact `.service` names and cgroups an absolute canonical path ending in that unit. Control fields identify the remote Control endpoint for this local role; two endpoints may use independently issued files with different counterparty IDs. Receiver-side Agent selection must still share its exact loaded source with that receiver's Control custody. Role tags differ even when the explicitly configured UID/GID or executable is shared. Control's tag identifies its configured mechanism role; Agent's tag supplies the private existing coordinator mechanism principal after every runtime field has matched. Neither tag grants an action, resolves a PageOwner or proves user intent. The checked-in golden uses zero pins and fixture accounts; it is a parser example, never production configuration.

The loader opens each absolute ancestor without following symlinks and retains its descriptor. Directories must be owned by local UID0 and have no group/other write permission. The leaf must be regular, UID0, singly linked and nonempty within 8192 bytes, with no group/other write permission. O_NONBLOCK prevents FIFO custody from blocking before type refusal. The same descriptor supplies bounded pread bytes and SHA256. Named and retained leaf dev/inode/mode/UID/GID/size/link/mtime/ctime (access time is excluded), ancestor dev/inode/mode/UID/GID and actual `/proc/thread-self/ns/user,mnt,time` identities are compared before and after reads. The named root is checked as well. A worker thread's namespaces are measured, not the process leader's. An observed mismatch retires the shared loaded source permanently; restoring bytes, inode names, modes or namespace does not revive it. This finite measurement does not promise closure of every asynchronous kernel/opcode window, whole-filesystem rollback prevention or a persistent policy revision floor.

Control selection consumes the existing `RootPathControlConnection` and existing opaque `AcceptedStreamCustody` through the rooted retained-only bridge. No raw Control FD, naked permanent policy or replacement accepted deadline is exported. The private `control_owner/root_path/approved.rs` constructor installs the source guard before the first low-level challenge; the old public constructors stay unchanged. The configured source guard follows original live Control ownership, retained cancellation/report owner and request custody. Agent selection must refer to the same loaded source already retained by Control; reloading identical bytes cannot approve an old received stream. Agent admission uses only `ProcfsPeerAttestor::default`, the original AF_UNIX peer and explicit configured UID/GID/unit/cgroup/pin. Cross-UID `/proc/<pid>/exe` EACCES refuses without a static fallback.

All five existing `ControlRequestVerifier` entrypoints retain the source: ensure_alive, ensure_pair_alive, verify_current, verify_pair_current and deadline. Both action and report checks compare it before and after peer checks. Execution Drop/revoke remains one-way; independent reporting can publish one already sealed own-journal terminal only while its original peer/path/configuration remains current. Reporting never restores action authority. Fork checks creating PID before copied state/atomics/callbacks; ordinary child destruction closes only descriptor copies and performs no shutdown, unlink or flock unlock.

The effective deadline is the minimum of the original policy Instant, original root Control Instant and original accepted Instant. Selection, transfer, queue, native source callback and report cannot allocate a new 20 seconds. The policy load accepts no ceiling above 20 seconds. Synchronous procfs and filesystem operations are not preemptively cancellable; every late return refuses. Pre-custody kernel accept waiting is not covered by this API.

The additive `product_dispatch/product_approved_policy.rs` module provides `ApprovedRetainedProductConnection`, which binds that same received stream, default live Agent, configured private principal and existing monitor. `ProductRequestCoordinator::from_approved_retained_connection` requires this opaque bootstrap; `serve_approved_retained_connection` compares its private principal and original current custody before the unchanged queue/preflight/native/receipt path. No public ServiceEvidence or foreign receipt manufactures a durable retirement. Existing AgentPort frame/golden bytes, public legacy APIs, binary defaults, service units, Cargo features, third-party identities and previous kernel/test methods remain unchanged.

The required tests are:

- `cargo test --locked -p hepta-peer-attestation --test approved_policy_kernel`: 17 real root/nobody filesystem/fork groups, including symlink/hardlink/FIFO, source changes and restore, retained FD inventories, a real mount namespace change plus restore and a worker-thread namespace change.
- `cargo test --locked -p hepta-browserd --test approved_policy_product_kernel`: 12 actual three-process/transient-systemd groups, including five verifier entrypoints, pre-serve source refusal with zero lifecycle facts/original client EOF, own-journal terminal, wrong explicit Control pin and five wrong Agent fields, different loaded source refusal, live cross-UID EACCES, cancellation, fork and earlier original policy expiry. The unit/cgroup and owned known test ELF pin are provisioned BEFORE either peer launch. Native completions in this test are synthetic queued source callbacks, not Servo.
- `python3 -m unittest discover -s tests -p test_approved_mechanism_policy.py -v`: closed contract/API/golden/workflow correspondence and source mutations. These tests do not replace the real kernel corpus.

The dedicated workflow runs actual head and prospective-merge source graphs with explicit source identities. Missing root, systemd, namespace or kernel capability fails its required fixture rather than silently skipping. Source success provides no installed broker, cross-UID production qualification, native final effect or release authority. The root/nobody fixtures use private owned new paths; they never deploy the golden to `/etc` or repair existing authority paths.
