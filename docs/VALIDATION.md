# 验证、性能与证据

版本：0.1。状态：测试设计；本文没有已执行的内核运行结果。

## 1. 结果分类

`not_tested`、`pass`、`fail`、`timeout`、`skipped`、`unsupported` 分别记录。运行模式与结果分开：在 VM 内通过的应用仍是 VM 模式。每项结果有应用/内核/环境范围，不能从一个成功用例概括整个生态。

## 2. 测试层次

| 层次 | 内容 | 不能替代 |
| --- | --- | --- |
| 单元/性质测试 | 编解码、句柄代际、预算、状态机、整数边界 | 真实中断、DMA 或应用兼容 |
| 宿主模型测试 | 受限 mock、并发模型、随机输入、客户端 | 新内核硬件执行 |
| QEMU 集成 | 启动、隔离、异常、ABI、virtio | 裸机、目标 GPU 和手机 |
| Linux 差分 | 固定 ELF、系统行为、应用结果 | Android Framework 和认证 |
| Android 场景/测试集 | APK、ART、Binder、图形、设备接口 | 外部服务必然接受该设备 |
| 裸机验证 | 真实固件、设备、功耗、恢复 | 其他机器型号或架构 |
| 产品工作负载 | Hepta 完整路径、本地模型、多应用、长期运行 | 未测负载的可靠性 |

## 3. 首个垂直闭环的操作步骤

1. 固定新内核、rootfs、Hepta commit/二进制、CPU 模型、设备和配置；启动后读取真实 boot identity。
2. 在新内核里启动真实 Hepta 与两个 CPU 工作负载，记录各自内核任务身份和资源域。对照工作负载不得由 Hepta 进程的生命周期自动带走。
3. 使用固定策略运行一轮，保存每个任务的 CPU 时间、总吞吐与请求延迟，说明采样窗口。
4. 经现有 Hepta 主链发出 InstallBudget，记录最终内容、权限范围、调用身份、返回的策略 revision。
5. 由独立于请求者的观测程序读取内核计数，确认目标预算生效、整体计费正确且没有跨域扩大权限。
6. 发送无权限目标、旧 generation、过期授权、重复 ID 不同内容和并发冲突更新，确认拒绝且状态不变。
7. 终止模型服务、执行桥或 Hepta；确认默认策略/预定义回退生效，独立应用、必要 I/O 和本地恢复仍可用。
8. 重启内核，确认旧句柄失效，未完成语义操作由原 Hepta 所有者核对，未知结果不会自动重发。

步骤 4 若只是启动 shell 调整 Linux 宿主参数，不算此闭环。步骤 5 若只读取模型自报的成功文本，不算独立观测。

## 4. 故障注入表

| 注入点 | 期望行为 |
| --- | --- |
| 请求头任意截断、过大 payload、长度溢出 | 拒绝，无内核越界和状态变化 |
| 授权后修改用户缓冲区 | 执行已复制内容或拒绝，不执行未授权变化 |
| 关闭后复用句柄、重启后复用 PID | 旧身份不作用于新对象 |
| 多线程同时安装预算 | 仅一个 expected_revision 成功 |
| 队列满、内存满、CPU 饥饿 | 明确限流/失败，恢复资源仍保留 |
| 设备提交后执行桥崩溃 | 保留可查询结果或 unknown，不盲重发 |
| 设备超时、移除、reset | 停止新提交，按协议完成/排空后回收 |
| 撤销与 DMA 并发 | 不产生新提交，不提前释放设备仍用页 |
| 持久化提交/flush/rename 前后重启 | 原数据模型可恢复，失败真实暴露 |
| UI 崩溃、网络失联、模型加载失败 | 内核和独立恢复入口不依赖这些组件 |
| 升级中断或状态版本不匹配 | 回退兼容前驱或进入恢复，不静默损坏 |

## 5. 性能比较设计

比较 A：同一新内核上的固定策略与 Hepta 策略。

比较 B：相同硬件、数据和任务，在原 Linux 与新内核上运行。

比较 C：原生、ABI 和 VM 模式的差异，单独报告模式及设备路径。

测试冷/热启动、多种负载以及多轮重复；固定输入、随机种子和运行顺序或进行随机化，并记录温度/后台负载。报告样本量、分布、p50/p95/p99、均值或吞吐与置信区间。低样本的尾分位数不做强结论。

初期不承诺“快 20%”等无依据目标。首个 CPU 预算实验先要求计费与隔离正确，再测额外开销。任何性能目标要在基线测得后固定，不能看到结果后倒改门槛。

AI 收益不能只统计优化后时间，必须计入推理成本、策略安装成本、观测开销、失误与恢复代价。保留不使用 AI 的固定策略作为对照和可靠回退。

## 6. 本地推理单独验收

记录模型与量化文件哈希、推理引擎、驱动、设备、实际执行进程、输入与输出。除吞吐和首响应延迟外，核对数值正确性、资源峰值、取消、设备异常和长期运行。

云端调用或另一个 Linux 机器上的推理只能算远程服务集成；不能当作新内核的本地 GPU 支持。显示输出和软渲染不能代替计算结果。

## 7. 最小结果记录

每次实验记录：run_id、日期、源码与构建哈希、host/guest 内核身份、硬件/虚拟设备、rootfs、应用哈希、运行模式、配置、命令、退出码、日志路径/哈希、预期与实际结果、失败复现。日志不可包含凭据或用户隐私。

可用普通 JSON/文本与现有 CI artifact 存放，不建立独立证据服务或多级签名系统。记录证明实际执行了什么，不凭字段名授予权限。大镜像和原始日志不塞进 Git 历史；仓库保留复现入口和结果摘要。
