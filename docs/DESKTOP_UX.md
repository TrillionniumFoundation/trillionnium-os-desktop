# 桌面与交互开发方向

版本：0.1。状态：产品与接口要求，尚无 UI 实现。

## 1. 原生界面

桌面和核心交互以 Rust 实现，围绕对话、任务和应用工作区组织，而不是以控制台页面作为主界面。终端、日志和调试信息作为任务内的可选面板；它们不是产品首页。

UI 框架和合成器实现暂不锁定。选型应验证中文输入、字体、无障碍、多窗口、低延迟输入和软件渲染恢复能力。不要为了框架偏好把必要功能改成外部浏览器宿主。

## 2. 用户能看到的对象

主界面显示当前对话、任务状态、运行应用和需要注意的真实结果。每个任务可以展开资源消耗、应用窗口、操作记录和停止入口。AI 失效时用户仍能启动应用、切换窗口、访问文件和关闭任务。

资源调整应显示“已应用的 revision 与实际统计”，而不是只展示模型说它做了什么。submitted、completed、failed、unknown、cancel_requested 的不同状态必须保留。

## 3. 应用模式不能隐藏

应用详情显示 native、Linux ABI、Android runtime、VM 或不支持，以及实际使用的软件/硬件渲染路径。界面可统一，但不能把统一外观当作兼容方式相同。

Linux 桌面协议与 Android SurfaceFlinger 的接合是独立工程；窗口能显示不代表输入法、音频、屏幕分享和后台恢复都已支持。[Android 分层来源](SOURCES.md#aosp)

## 4. 可信交互边界

焦点与输入目标由可信合成/输入服务决定，普通应用不能截取其他工作区按键。授权提示必须带系统可识别来源，应用内容不能伪装成系统权限。

截图、剪贴板、拖放和文件选择使用窄的共享接口；默认只共享用户明确选择的对象。Hepta 可以在既有授权范围内自动操作，不获得永久全屏录制或全局键盘监听的隐式权限。

模型生成内容与真实应用/系统状态在 UI 中明确区分。后台操作失败或结果未知不能被对话中的“完成了”遮盖。

## 5. 交互验收

中文输入与候选窗、键盘/触控、焦点切换、多窗口、缩放与旋转、通知、剪贴板、应用退出和桌面重启逐项验证。恢复模式允许简化图形或文本界面，但不能以恢复控制台代替日常产品 UI。

跨 Web/桌面的设计可以共享 Rust 领域模型与协议；共享设计不意味着本地 OS 桌面依赖 JavaScript 运行时。是否提供 Web 管理端另行实现，不成为新内核启动条件。
