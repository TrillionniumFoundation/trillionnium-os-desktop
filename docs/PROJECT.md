# 项目范围与需求

版本：0.1。状态：设计基线，未实现。

## 1. 产品定义

构建能够独立启动、隔离进程、管理资源并控制硬件的新 Rust 内核。Hepta 是原生系统服务与智能控制平面；Linux ELF 和 Android APK 是需要承载的应用生态，而不是要求底层继续使用 Linux 的理由。

“AI-native”在本项目中的含义是：任务语义、资源预算、设备能力、执行状态和用户目标能够在 Hepta 与 OS 之间以稳定、可验证的接口关联。它不等于在 Linux 桌面放一个聊天窗口，也不等于让模型在特权态直接写任意寄存器。

## 2. 必须保留的需求

| ID | 需求 | 验收口径 |
| --- | --- | --- |
| R01 | 新内核核心以 Rust 实现 | 核心源码、底层依赖、必要汇编与 unsafe 边界可检查 |
| R02 | 内核可独立于 Linux 启动 | QEMU 启动只是阶段证据；最终至少一台受支持实机裸机启动 |
| R03 | Hepta 原生控制资源与硬件 | 存在真实请求到内核对象或驱动的完整路径，不仅输出 shell 文本 |
| R04 | 尽量无修改运行 Linux 程序 | 固定 ELF、用户态镜像、ABI 和具体功能进行行为测试 |
| R05 | 尽量无修改运行 Android APK | 固定 APK、AOSP、ISA、设备功能及服务依赖进行完整场景测试 |
| R06 | 明确兼容模式 | 每个工作负载报告 native、linux_abi、android_runtime、vm 或 unsupported |
| R07 | Hepta 故障不导致基本系统失效 | AI 进程被杀、模型不可用、网络断开后独立应用与必要 I/O 继续工作 |
| R08 | 本地资源执行不依赖远程协调 | 远程 Fleet/模型/共识断开不得阻断本地停止、撤销、调度和恢复 |
| R09 | 自动化不过度审批 | 在已授权范围内自动执行；权限和资源检查由机器实施，而非每步人工确认 |
| R10 | README 留空、文档集中 | 根目录 README.md 为零字节，开发入口为 docs/INDEX.md |

## 3. “所有应用兼容”的可执行定义

长期目标是持续扩大现有 Linux/Android 应用覆盖，不擅自将目标缩减为只支持自己重新编译的程序。阶段验收必须固定：应用版本与文件哈希、指令集、依赖镜像、用到的内核接口、硬件、外部服务和场景。没有定义清楚的无限集合不能用一个百分比声称已完成。

兼容层不自动提供跨指令集执行，也不自动提供 Linux 内核模块 ABI。第三方服务器是否接受设备、是否提供服务，与本地程序行为兼容分别记录。[来源](SOURCES.md#linux-abi) [来源](SOURCES.md#android-native-bridge) [来源](SOURCES.md#play-integrity)

允许 VM 为尚未原生实现的应用和设备补缺，但不能把 VM 内的 Linux 当作本项目 Rust 内核，也不能将“VM 可用”记为“原生兼容通过”。保留将 VM 依赖逐项迁回原生实现的接口边界。

## 4. 首个垂直闭环

在新内核上运行真实 Hepta 组件与一个未修改 Linux 工作负载。Hepta 观察资源竞争，通过原生 ABI 调整该任务的 CPU 预算；独立观测验证预算确实作用于调度；随后强制退出 Hepta，确认内核、独立应用、必要 I/O 和恢复入口仍可使用。

这一闭环首先用 CPU/受控 I/O 实现，不等待 GPU。它只证明本次选定接口与工作负载，不代表整个 Hepta、所有 Linux 应用或 Android 已兼容。后续单独完成完整 Hepta 路径和本地模型推理。

## 5. 范围与非目标

首期集中 x86_64/QEMU/virtio，随后固定一台物理机；ARM64/Android 为明确的后续工作线。开发机能够运行工具链，不等于已列入新 OS 的硬件支持清单。

第一阶段不同时重写 ART、Android Framework、所有桌面协议、所有文件系统或所有推理引擎。不复制第二套 Agentd/Codex 主执行链，不把模型、SQLite 或复杂授权数据库放入中断和调度快速路径。

“Rust 内核”不意味着现有 Android 用户态也必须全部改写为 Rust。复用上游必须保留来源和适用的许可文件；不能将派生实现宣称为完全从零原创。具体许可选型在首次导入代码时记录，此文档不擅自为未导入代码赋予新许可。

本次仓库重建仅作用于该 GitHub 仓库。不更改 hepta-private-ci，不替换任何现役机器内核，不迁移现有服务，不刷手机或 BIOS，不删除任何主机上的旧工作树。

## 6. 成功指标

按真实任务的成功率、尾延迟、吞吐、资源使用、能耗和恢复结果评估。代码行数、文档数量、启动画面和“AI 调过一次工具”都不是生产可用的替代指标。具体实验由 [验证计划](VALIDATION.md) 定义。
