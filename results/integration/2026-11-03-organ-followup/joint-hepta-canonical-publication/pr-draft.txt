## Problem and resulting behavior

The frozen Desktop product uses the original Notes-only owner, while the second Calculator application and its typed receipts were developed as separate components. This integration candidate connects both applications to one original Core thread, one original Objective sender and the same protected durable writer. It also fixes two lifecycle boundaries discovered while assembling the real Linux product: a text connection could consume the whole remaining Root lifetime before its first byte, and App Server recreated its Unix signal subscriptions between loop iterations.

## Review by owning boundary

| Boundary | Changes and resulting behavior |
| --- | --- |
| Original writer and Objective sender | Calculator uses its own exact payload, target and typed receipt. Notes and Calculator share one durable attempt per original Core turn, including an uncertain preparation. A later callback cannot relabel the first application's receipt or acquire another attempt by changing call ID or target. |
| Original Core integration | A separate six-tool Desktop catalog and seed bind the original connection, thread, callback, arguments and human admission. Retained sender state takes precedence over incomplete activity listings; status paths do not dispatch an effect. |
| Root, Session and Agentd startup | A distinct sealed Desktop profile binds both actual application targets and the original Session lifetime. One original startup deadline covers the handoff, protected recovery, activation and both application offers. Notes-only profiles and old receipts retain their own schema and meaning. |
| Text UI lifetime | The first byte and remaining frame share the original bounded exchange deadline, also capped by the actual remaining Root lifetime. Storage work is not described as forcibly cancellable. |
| App Server shutdown | Unix signal receivers stay registered across cancelled receive futures. Three isolated owned-child tests acknowledge actual TERM/HUP/INT handling through private datagrams; the ignored child helper is not counted again as a parent test. Existing drain behavior stays intact. |
