# Exact-pin S08 Servo qualification adapter

This directory contains the test-only source appended to Servo's existing `components/servo/tests/accessibility.rs` after the reviewed retained-node patch is verified. It is not a standalone crate, product adapter, installed binary, listener, or alternate browser runtime.

The permanent S08 workflow compiles this source inside exact Servo commit `670ae8a70801b162e186f81cbb5bdd2d59c39108`, starts one real WebView-owning test process, and connects it to the product-side AgentPort/BrowserActor/receipt integration test through an absolute private atomic-file mailbox. It requires real navigation, AccessKit observation, retained-node click, exactly-one callback completion, DOM mutation, second navigation, and close. New semantic source checks and ordinary parser fixtures do not establish that the changed complete Servo program has compiled or passed; the exact-pin execution must run again.

The original S07 parts remain unchanged. After those parts, `manifests/lab-s08-semantic-custody.v1.json` applies one separately bounded patch. `WebView::observe_accessibility_semantics` obtains the snapshot from the actual current script/layout owner after reflow. The adapter sends that real tree/node identity, role, name SHA-256 and structural fingerprint through the existing Actor `ElementReference`. `WebView::perform_checked_accessibility_action` retains the typed expectation across dispatch and compares a new actual retained snapshot in the final script task before one click. A buffered consumer tree cannot supply its own epoch authority.

The independent real Servo corpus mutates the same node's label, role or ancestry, replaces its identity, disables or hides it, and supplies an earlier epoch expectation. Every case requires its exact typed refusal, one callback and a zero actual DOM click counter. The ordinary 10 AgentPort requests, 9 Servo commands, 30 durable receipt facts and one positive click remain required, as do all original S07 retained-action tests.

`semantic-source-check/Cargo.toml` and its lock are templates for `python3 tools/verify_s08_semantic_custody.py --source-check`. The verifier extracts the actual new upstream module into a private temporary crate and runs its six tests with Rust 1.93.0 and the exact pin's registry dependency versions/checksums. This checks the bounded encoder, SHA preimage and typed schema. It is not a standalone browser or a Servo execution result. `--check-upstream` first verifies a pristine exact-pin checkout, then applies old and new patches only in a disposable source copy and verifies every declared original Git blob, post-S07 bytes and semantic after-source digest. The checkout remains pristine on success and failure. New semantic hunks allow no offset or fuzz; original part 006 retains its previously qualified context fuzz.

The mailbox protocol and synthetic procfs facts are qualification fixtures only. They provide no product IPC, installed-systemd, external-network, hardware, signing, publication, or release authority. See `docs/architecture/S08_SERVO_BROWSER_ACTOR_VERTICAL_SLICE.md` and `contracts/s08-servo-runtime-bridge.v1.json`.

The semantic patch does not refresh Agent/control pidfds inside Servo's final script task. The existing bridge checks its request custody before the test mailbox command and at completion. Joining that custody to an installed native PageOwner/effect boundary remains a separate integration requirement.
