# Kernel wrapper lifecycle — host fixtures only

Accepted source: `4b3153079336ddea244c2ffecea1da0e006769b6`, tree `6860909e4645acdc9c4e0ed4f6eb215dac63d139`. The publisher verified this tree against local `536a544d6578c7eb5dc9efbc72035ad1cda53ffc`; exact parent and all four file hashes are in `source-binding.json`.

The unchanged baseline wrapper was copied into a disposable host fixture with dummy make and Python TCP-lease processes. Direct SIGTERM exited the wrapper(-15) and removed its owned manifest while make, its child, two TCP leases and the inherited workspace lock remained active. Direct SIGINT left wrapper/make/child and those resources active after two seconds. These are actual process observations, not VM results. Both fixtures then cleaned only their owned, still-anchored groups; all observed pidfds exited. The real untracked manifest was only read and its hash stayed unchanged.

The public wrapper now execs a cooperative Python supervisor. Signal handlers only retain the first signal, so Popen assignment and normal cleanup cannot unwind asynchronously. The owner retains its worker leader with WNOWAIT until TERM/KILL group cleanup precedes reap; ECHILD disarms signaling. Debug explicitly routes with `A01_KERNEL_WORKER=1`, reusing its existing outer owner instead of creating another session. This flag is lifecycle routing, not security authorization or a PID/PGID heuristic. Existing manifest inode guards, stable flock, three make targets and GDB descriptor inheritance remain.

Accepted final checks passed9 new supervisor tests plus10 existing wrapper tests under each of `-I -B` and `-I -O -B`. Full-wrapper INT/TERM plus repeated TERM prove pidfd exit, released TCP leases/lock, stable lock inode and manifest removal. Real INT→TERM at Popen publication and at normal cleanup's first group signal preserve first SIGINT/130 and complete cleanup. Other tests cover normal success with a lingering child, debug routing, GDB FD>=64, already-reaped entries and ECHILD. The GDB handoff fixture deliberately fails ordinary boot acceptance because it starts no VM.

The first throwing-handler/SIG_IGN implementation passed initial tests but was superseded after parent review; its source hashes and raw logs remain clearly separate from accepted final tests. Preliminary cooperative logs also remain historical. Three exported patch paths were actually restored in disposable partial trees and matched all expected source hashes: baseline→first intermediate, intermediate→accepted final, baseline→accepted final. Full production source copies, generated initramfs blobs, targets and binaries are omitted.

All results in this package are host fixtures or read-only checks. No Rust kernel was built, no QEMU/VM was started, and no SMP/VMX/cross-host reproducibility claim follows. Public cancellation requires catchable INT/TERM; uncatchable SIGKILL cannot run cleanup. Composed debug calls must keep the explicit worker route. This owner assumes it is sole reaper of its direct worker; ECHILD fails closed. The independent reviewer checked ownership logic without rerunning tests. Raw logs/observations include every retained intermediate run; `raw-logs.members.json` hashes each tar member, and `SHA256SUMS` hashes this package. No active clean build worktree was read or modified.
