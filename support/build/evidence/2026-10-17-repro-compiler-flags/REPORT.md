# Enforce the compiler remap after the real kernel failure

The first normalized full kernel from published source `542e09ebf0471124a01e3d721b531a29e141e54b` compiled, then actually entered Rust/OSTD in QEMU and panicked with `NotIncludeAllComponent("/tmp/trillionnium-a01-normalized-A/kernel/asterinas/kernel/core/comps/virtio")`. This is a retained failure, not a passing boot. The serial panic still named the real core init.rs path. Profile, source Components and profile-code custody all remained unchanged.

The actual compiler log has 369 invocations. All 138 x86_64-unknown-none invocations lack a remap. In contrast, 123 host/probe and 7 Linux host-target invocations have one. The pinned OSDK CLI constructs action configs, then appends environment RUSTFLAGS only to global config.build; do_cached_build uses config.run.build. Consequently direct host Cargo honored the requested environment flag while the actual kernel action omitted it. The metadata adapter had already projected the component keys, so the unchanged real compiler file! keys could not match.

The support-only fix is published as `bdf7a08dcc0980fa85c0ba5abdf365b7d2c42e80`. The wrapper now retains every original compiler argument, enforces the canonical policy remap before an optional -- delimiter, rejects conflicting overlapping maps, records incoming/effective vectors and executes the latter. The unchanged metadata adapter uses that same real/virtual map. No upstream, core, OSTD or OSDK source was changed. New schema/code hashes require a new profile directory and new empty targets; the old failed A run, target and profile are preserved.

The actual fixed-nightly native CLI probe deliberately sets RUSTFLAGS empty. Its direct compile exits 0 and the unremapped host program exits 101 at the path assertion. Through the private wrapper, compilation and execution both exit 0 and file! prints the virtual filename. An original --cfg is required by compile_error!, proving it survived; the wrapped -Vv probe also exits 0. Eighteen focused candidate tests pass in isolated normal and optimized Python modes, with directly captured return codes. These native host programs are not kernel artifacts or kernel acceptance.

source-bindings.json ties all six tested candidate files to their exact published Git blobs and modes. The chunked deterministic archive retains actual probe source, commands, stdout/stderr, native ELF gzip payloads, both test logs and direct exit receipts, compiler input/output argv, and the old real kernel's complete console/serial/compiler log, command, environment, source check, QEMU and cleanup/result records. Failure-observation.json is a readable diagnosis; full raw failure data remain preserved at their original locations too.

Run `python3 -I verify.py` to check outer files, ordered parts (each at most 2 MiB), the reassembled SHA256, every tar member and the original inner checksum closure. Two independent archive builds were compared byte-for-byte. `--output /absolute/new.tar.gz` additionally saves a verified new archive and refuses an existing path. artifact-bindings.json inside the tar records original raw ELF/log hashes alongside their retained gzip representations. Full A2/B2 kernel acceptance and cross-host proof are separate work; neither is claimed in this phase.
