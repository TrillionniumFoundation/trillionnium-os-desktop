## 2. 实际构建与启动入口

先按 `support/build/README.md` 准备固定工具链、QEMU、固件、BusyBox 和 vDSO，让 Rust/Cargo、QEMU、构建工具可从当前 `PATH` 找到，再进入项目根。以下是可移植的重放命令；`/absolute/path/to/...` 均为需要替换的示例路径：

```sh
cd /absolute/path/to/trillionnium-os-desktop
unset CARGO_ENCODED_RUSTFLAGS CARGO_TARGET_DIR
export RUSTUP_TOOLCHAIN=nightly-2026-07-21
export CARGO_BUILD_JOBS=2
export A01_SMP=1
export HEPTA_G1C_TRUSTED_OBSERVE=0
```

若采用系统常规安装，沿用脚本的默认工具选择。若像本轮一样采用私有提取的运行环境，还须按实际安装位置设置以下变量，并把相应工具目录加入 `PATH`；QEMU 模块路径必须对应正在执行的同一套 QEMU：

```sh
export PATH="/absolute/path/to/runtime/usr/bin:$PATH"
export LD_LIBRARY_PATH="/absolute/path/to/runtime/usr/lib/x86_64-linux-gnu:/absolute/path/to/runtime/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export A01_BUSYBOX=/absolute/path/to/runtime/usr/bin/busybox
export A01_QEMU_BIOS=/absolute/path/to/runtime/usr/share/seabios/bios-256k.bin
export A01_QEMU_DATA_DIR=/absolute/path/to/runtime/usr/share/qemu
export QEMU_MODULE_DIR=/absolute/path/to/runtime/usr/lib/x86_64-linux-gnu/qemu
```

构建与启动（下列两个输出目录必须尚不存在）：

```sh
A01_RUN_DIR="$PWD/support/build/out/replay-build" support/build/kernel.sh kernel
A01_RUN_DIR="$PWD/support/build/out/replay-boot" support/build/kernel.sh run_kernel
```

入口调用上游 `make kernel` / `make run_kernel`，通过 `support/build/minimal.mk` 使用小 BusyBox initramfs、固定生成 lock 和每次运行私有安装的 OSDK。本地原始归档中的各运行目录保留 `command.sh`、实际 QEMU argv、固件/产物 hash、串口和退出状态；公开摘要不冒充原始命令或完整环境记录。初始配置为 x86_64、q35/TCG、CPU max、1 vCPU、512 MiB、SeaBIOS、串口与 debug-exit，无外部数据盘或网络设备需求。

本轮已实际安装固定 nightly（含 rust-src、rustc-dev、LLVM tools）、cargo-binutils 0.4.0、QEMU 8.2.2、SeaBIOS 1.16.3、BusyBox 1.36.1、cpio 2.15、GDB 15.1；Clang/LLD 18.1.3 为已记录的现有宿主工具。Docker、Nix、KVM 不可用，采用 TCG 路线；不需要 NixOS ISO。依赖安装原始证据保存在 `runtime-installation-2026-10-20.tar.xz`，并非跨宿主完全不可变环境的认证。

## 4. 普通启动与 G1-c 的覆盖边界

普通内核构建保持 **QueryAbi-only**。G1-c 需要显式 `HEPTA_G1C_TRUSTED_OBSERVE=1`、固定受审的 `HEPTA_TRUSTED_INITIAL_ELF` 及专用 guest runner；普通 `kernel.sh run_kernel` 不承担该实验入口。G1-c 的初始 Process 观察槽位为 1/1，lease 300 秒，绑定原 CPU owner 的 50ms/100ms 配置；open、dup、fork 或 fd 转移不自动授予该权限，管理与历史操作仍禁用。

本轮两次普通 boot 已证明对应 producer 的默认内核真实启动；这不扩展为 G1-c 授权路径、CPU 节流工作负载、完整 G1 或 Hepta G2 端到端通过。

### 已解决的运行环境故障

第一次尝试在 QEMU 进入内核之前失败，原始错误是 `could not load module for type 'tcg-accel-ops'`。私有提取的 QEMU 模块位于宿主编译前缀之外；补充 `QEMU_MODULE_DIR` 指向私有 `usr/lib/x86_64-linux-gnu/qemu` 后，两次 boot 和两个完整 crate suite 均实际通过。该修复只调整本任务运行环境，没有更换内核版本或修改核心源码；原失败命令、环境、stderr 和空串口记录保留，**不再列为未解决 blocker**。
