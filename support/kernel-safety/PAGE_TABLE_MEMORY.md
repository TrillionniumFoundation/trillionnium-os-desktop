# User page-table memory, third isolation stage

This stage adds real user page-table frames to `hepta.page.*`. It does not enable Linux `memory.max`, account every kernel allocation, reserve global recovery memory, or qualify the kernel for production isolation. M2's private/COW, anonymous VMO and file-cache ownership rules remain in place.

## API and ownership

`hepta.page.stat` adds `page_table`; the total and ancestor ceiling include this class. Each newly allocated user root, upper directory or leaf table reserves one physical page before physical allocation. OSTD retains an opaque owned reservation in the frame metadata and drops it only when that frame's final reference disappears. Physical allocation failure drops the reservation. OSTD exposes a safe fallible `VmSpace` constructor and mapping operations; the kernel supplies the account callback.

The callback reads the allocating process's current cgroup through RCU and reserves its leaf and ancestors using the existing IRQ-safe account locks. The callback is invoked under atomic/page-table guards and must not sleep or call page-table operations. It carries a function pointer into child nodes, not a fixed address-space account: migration affects each subsequent node allocation. A previously allocated node continues to charge its original account. Fork's new tables charge the forking process; a CLONE_VM share creates no root. Later faults by another member sharing that address space use that allocating process's membership. No process means an explicitly unaccounted token, as in M2.

Shared kernel-space entries are copied into a new user root without charging their shared nodes to the process. Kernel/IOMMU page tables keep their existing unbudgeted constructor. Charged user tables support base-page translations only; enabling huge user pages requires fallible split/unmap/protect admission first. The boxed reservation's heap allocation and its metadata overhead are not in this physical-page ledger.

## Failure propagation and publication

- Root creation returns ENOMEM before publishing a new address space. Fork and exec propagate it to userspace. Fork can also fail after creating part of the child table; the unpublished child owns and releases that partial tree. Parent COW write protections may remain, but no child is published and subsequent parent faults retain normal COW semantics. A stale writable parent TLB has no newly visible child sharing those frames; successful forks still complete the existing global parent TLB flush before child publication.
- Query, protect and unmap of a hole allocate no page-table frames. Cursor acquisition locks an existing ancestor when the requested subtree is absent. It preserves the requested barrier and permitted mapping level, even when the actual lock is broader. Existing locking, RCU and query-contract tests remain enabled.
- Mapping allocates intermediate nodes fallibly before publishing the data-page PTE. Failure drops the incoming frame reference. Already constructed empty table nodes remain allocated and charged; admission does not pretend they were freed. Fault paths return ENOMEM through the existing fault-to-signal handling.
- `mremap` preflights only destination paths corresponding to resident source pages. It holds the same cursor through preparation, metadata updates and page moves, so another cursor cannot remove a prepared node between admission and use. A preparation failure leaves source PTEs and source mapping metadata intact. As in the existing implementation, an earlier requested shrink or MREMAP_FIXED destination truncation may already have occurred; this is not full syscall rollback for every destination side effect. A dedicated guest negative test verifies the retained source byte while confirming those existing tail-unmap and target-truncation side effects.
- Device map handles preflight the complete destination before publishing I/O mappings. The lower OSTD fallible I/O mapper also retains the `IoMem` owner before its first PTE, so an error after a mapped prefix cannot leave dangling I/O ownership. The documented partial-prefix behavior and actual VmSpace owner storage are tested directly without accessing hardware at the synthetic I/O range. The existing global `IoMem` range allocator does not recycle acquired ranges on Drop; this stage does not change or claim that behavior.

Lock order remains VMAR metadata, reverse mapping when applicable, page-table cursor, then one page-budget account lock at a time. No page-budget lock spans allocation. Prepared mappings hold no account lock across publication. A rejected ancestor rolls back already-reserved descendant counters.

## Release and recovery limits

Unmapping a page may leave an empty page-table node allocated. Clearing or dropping an address space and actual table-subtree reclamation eventually release those nodes; the counter follows real ownership. TLB/RCU references delay frame destruction. An activated `VmSpace` is also retained by each CPU until another address space replaces it on that CPU. Consequently even process exit does not promise immediate root-table refund or any wall-clock bound on a stalled/idle CPU.

The limit prevents additional covered page allocation in an exhausted subtree while an outside observer can adjust it. It does not stop allocations from kernel heap/slabs, stacks, direct filesystem metadata, device/DMA buffers, system/shared page tables or processless work. Existing pages owned by another group remain usable, subject to admission of any new local table nodes. The global allocator and all those uncovered classes can still exhaust physical memory. A sibling recovery group's counter is not a protected physical reserve.

Next stages require task/stack and kernel-object ownership with fallible publication, delegated worker/DMA charges, and actual protected physical/metadata reserve pools with reclaim/writeback/OOM policy. Renaming this partial controller to `memory.max` would misstate its coverage.

## Build, probes and evidence

Use the pinned nightly and an OSDK compiled from the same checkout; never reuse an OSDK embedding another worktree. Run full OSTD and aster-core native suites through `support/build/ktest/run.py`, plus page-memory ordinary guests on 2 and 4 CPUs. Run the existing safety probes and DMA-domain hardware probes because the generic cursor also serves DMA page tables.

The OSTD native probe uses real Frame allocations. It denies roots and successive directory allocations, checks allocation-free query/unmap/protect at the ceiling, retains correctly charged partial paths, checks final frame refund, and forces an I/O mapping prefix failure while its `IoMem` remains exclusively owned. It does not force global physical allocator OOM.

The ordinary guest uses real sparse mappings, fork, exec, mremap, memfd, ext2, cgroup migration and four simultaneous sparse workers. Exact-ceiling negatives require ENOMEM or the expected SIGSEGV and denial-event increments; positive tests verify bytes, per-class deltas and final-reference refunds. The observer's pre-existing shared backing specifically separates a table-only fault denial from data-page denial. Source snapshots and kernel/BIOS/initramfs/probe/serial hashes must match for a passing receipt. A passed development run is not a substitute for integration testing the receiving commit.

Initial failures are retained: four existing OSTD tests exposed absent-range query and mapping-level compatibility regressions, fixed without removing those tests; an added I/O test incorrectly assumed global IoMem reservations recycle on Drop (the replacement checks actual retained owner storage and both prefix PTEs); one core compile used an incorrect Result import; the first C compile rejected misleading indentation. These are not counted as passing qualification evidence. The first complete ordinary 2/4-CPU development runs each passed 112 assertions; final commit binding and subsequent results are recorded separately with the retained logs.
