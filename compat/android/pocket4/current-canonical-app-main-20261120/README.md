and input validation; it does not perform account add/remove, grant/revoke,

launches, routes, UI, writes or removals block automatic restoration; conflicts
are preserved rather than overwritten. A first Flow retains its held Main
descriptors after task removal so a failure constructing the second Flow can
still restore the known setting through the original lease. It creates no
additional Android task. Repeated writes and repeated restores are rejected.

Only a complete actual case can credit `settings.pages` and
`settings.roundtrip`. Every failure retains all original business gates.
The original permission definition in `bundle/source/contracts/app-gates.json`
