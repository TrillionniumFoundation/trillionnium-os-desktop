# CP3A provider source rebinding

The current source selection already contains verified CP3A APK and signer
identities for CalendarProvider, ContactsProvider, ExternalStorageProvider,
and MediaProvider. The historical business sources still use their old APK
hashes; Camera and Gallery rotation also still name the CP2A MediaProvider
APEX member. A current source receipt alone does not update those consumers.

This successor reproduces the existing five target-app adaptations and six
Gallery entry retirement guards from all 224 complete original source files.
It then changes 11 provider-bearing files: exact APK hashes and sizes, the
two MediaProvider APEX paths, and previously absent signer/size constraints.
The result is 24 combined source postimages. The provider transformation
preserves UIDs, helpers, limits, selectors, control flow, and finite business
and cleanup gates. Existing Gallery modified-APK installation and ART entry
points remain unconditionally retired.

`prepare_cp3a.py` is a deterministic metadata/source transformer. It imports
only the exact pinned original metadata transformer, never a runtime runner.
Every original source and source-evidence input has a size/SHA check and
before/after file-identity bookends. It checks all 224 files for residual old
provider hashes and old MediaProvider member paths. A new output is created
exclusively; old preparations and historical records are never rewritten.

`prepared/SOURCE-CONTRACT.json` contains the ten exact source identities:
six target apps and four providers. It includes the complete official
2,294,853,632-byte CP3A system-image SHA, distinct APK signer identities,
the official Gallery DEX/class/method source identities, and preserved UID
constraints. These constraints are not observations of installed UIDs.
MediaProvider's actual UID remains unknown. The CAPEX digest is not accepted
as the MediaProvider APK identity.

```sh
python3 -B compat/android/pocket4/current-app-acceptance/system-cp3a-provider-rebind-20261120/verify_prepared.py
python3 -B compat/android/pocket4/current-app-acceptance/system-cp3a-provider-rebind-20261120/test_prepare_cp3a.py
```

Both entries accept `--repo-root` for an isolated complete repository copy.
The verifier reconstructs every generated byte and verifies the whole packet
inventory. The 19 controls cover complete scope, residual old identities,
source-only flags, signer and whole-image drift, provider dependency removal,
CAPEX/APK confusion, old Gallery DEX substitution, literal-only source reading,
unchanged control flow/limits, preserved historical Calendar contracts, and
create-only output. Two actual local reconstructions produced byte-identical
sets of all 27 generated files.

## Remaining runtime work

These postimages have not been adopted by the original runtime preparation
bootstrap. The original Calendar standalone-install receipt and atomic-delete
review remain historical inputs; their contents are not relabeled as CP3A
evidence. Current provider cleanup semantics still require a new qualification.

Gallery still requires a real zero-install image-custody producer and a
separate current consumer, bound to the complete official GSI, committed cell,
fresh Main/framework epoch, current installed APKs and signers, original UID,
all 29 protected permissions, and retained CE/DE data identities. The existing
source-only GSI preparation is not a deployed-image receipt. The source-built
four-partition delivery schema is a different route and is not accepted as
official-GSI installed custody. Old modified-DEX ART and method credit do not
transfer to the official DEX.

No Main, Android, SDK, APK installation, image mount, private application-data
read, business execution, or production activation occurs in this packet.
All installed/runtime/business/production flags remain false. The required
39-app scope and the three existing exemptions are unchanged.
