# One settled target, two private service logs

The source preparer creates no remote job or claim. It first imports the exact
reviewed local permission gate and requires the selected batch's real complete
stage/owned-worker/authoritative-terminal joint PASS. A prior Beike result is
never substituted for a new target result.

The caller may select only one package from the fixed 13-partition capture
plan. It cannot supply a remote filename. The two allowed paths, lengths and
SHA256 values come exclusively from that target's successful `dump-package`
and user0 `appops get` service reports. They must equal the expected two
`android-NN.stdout` paths in that exact batch output directory and each must
fit the inherited 262144-byte command-stream bound. Unknown/failed/unsettled
capture stops before new reader source is produced.

The reader is derived from the actual successful two-log Beike reader. Only
PINS, descriptive labels and the recorded target/batch/job change. Its five
read/hash functions are preserved exactly: root-owned single-link regular
files, component-by-component nofollow opens, complete bounded bytes/SHA,
held-file and reopened-path equality over all nine stat fields, and explicit
finally-close for every acquired descriptor. It retains the original final
process FD-count equality check; this is not relabelled as a new whole-process
descriptor-census proof. Full identity checks apply to each actual held file
and path. No namespace, Main, action lock, APK tool, UI or permission command
is involved.

The generated source/packet are review-only and use a new fixed key once. The
coordinator requires actual durable success, complete original stdout and the
reader's final FD check before interpreting any result. A timeout or unknown
is preserved and reconciled only under the same original request/key.

Complete reader stdout, every process-read body and the two decoded files are
private. Their destination is a fixed subdirectory of `p4_private_ui` outside
the repository, recorded in each generated plan. Never pass this reader's
stdout through a public artifact-saving helper. Public Git may contain the
reader, exact request, input pins, start/terminal metadata and a hash-only
receipt. It must not contain the raw/hex permission-service content.

Interpretation is a separate offline step using the already frozen conservative
parser. It must verify the two recovered full byte streams against the same
successful capture pins. Unknown formats stay UNKNOWN; neither raw-reader
success nor AppOps modes create a new permission, role or production result.

Only the selected real successful batch/target is materialized. This design
does not prepopulate guessed pins for the other 44 packages or broaden root
read access.
