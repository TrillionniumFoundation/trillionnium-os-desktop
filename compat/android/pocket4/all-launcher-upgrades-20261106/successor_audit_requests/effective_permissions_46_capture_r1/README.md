## Capture design

There are 14 batches and 106 Android read-only commands: one package help in every batch, then package dump-package and appops get --user 0 for each of the 46 targets. Each batch also preserves the original native status/applications/status sequence. There is no ADB, shell command, UI/instrumentation, activation, install, role mutation, permission grant/revoke, or business-data read. Meituan's protected location state and original Bili UNKNOWN are checked by the existing helpers and remain unchanged.

The new normal template inherits all 21 original worker support definitions and all eight transport definitions exactly. The original held namespace helper, classpaths, immutable runtime guard, owned process lifecycle, empty-stream handling, unjoined-child poisoning, target closure, and lease cleanup are preserved.

The microG template alone copies the actually successful correction's held_bounded_child, capture_limits_for, and nested runner byte for byte. Its second exact command, cmd package dump-package com.google.android.gms, permits 2 MiB of stdout. The associated stderr, package help, AppOps, and every other package/command retain 256 KiB. The exact suffix and command index are checked. The command timeout remains 30 seconds, Android timeout 25 seconds, worker deadline 900 seconds, owned child 1000 seconds, outer process 1100 seconds. No automatic retry is added. The old correction's failed-batch linkage is not invented as a new runtime prerequisite; only its verified capture-budget and lifecycle implementation is inherited.

Each worker checks the exact 46-component native catalog against the actual framework resolver reference. Count equality alone is insufficient. A missing component, new component, duplicate, or package/component mismatch stops before service queries. These permission workers do not themselves rerun the framework resolver and will not claim that they do. The 49-package byte/stat identity guard remains independent of the 46 Launcher membership check.

The transport command table is also null. They are reviewable source templates, not executable requests. prepare_unsealed.py only reads fixed local public metadata and sources, creates new local files with O_EXCL/fsync/readback, and emits no controller request.
