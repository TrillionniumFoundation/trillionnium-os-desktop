## Signal-mask repair and owned probes

The repair keeps the interrupted signal mask in the current synchronous signal-handling path, exposes that mask in the guest ARM64 signal context, and commits supported guest mask edits through the real signal return. The candidate filters the unblockable SIGKILL and SIGSTOP bits, writes only the kernel mask's low 64 bits, restores CPU state before unblocking, and does not keep a host-frame pointer in a queue, thread object, global, or TLS slot. The source review is deliberately limited to that synchronous/direct-delivery scope.

## LMKD source and real bootstrap result

The [complete host freeze04 source](lmkd/host-bootstrap-freeze-04/source-manifest.json) includes the production-callable lifecycle broker, owner daemon, one-shot admission and retirement handling, ordinary IPC controls, and the owned lifecycle caller/actor. The public `LeaseOwner` retirement path now permanently records a worker-join panic so a second call cannot turn an unproven retirement into success. A real panic/retry Rust control is included in the matched test count.

The [complete Android r6 freeze](lmkd/android-build-freeze-01/freeze-manifest.json) includes request/grant handling, SCM_RIGHTS ownership, the relay session, event routing, accounting-root checks, synchronous effect guarding and tests. The relay requires a fresh real pressure observation; a live lease by itself cannot authorize a pressure effect. Lease loss revokes the generation and disables pressure effects until lifecycle restart. Each supported cgroup write or held-pidfd signal has its own final gate. The legacy numeric-PID `cgroup.procs` kill route is refused in relay mode.

The native original PSI defaults remain partial stall 70 ms, complete stall 700 ms, and a 1000 ms window; the existing low-RAM partial default remains 200 ms. Native requests carry the configured original values to host registration without lowering a trigger. A `full 70000 1000000` string in a Rust unit vector is a codec/configuration test, not the actual default critical threshold. The minimal default Android root is expected to request `some 70000 1000000` and `full 700000 1000000`; this checkpoint does not claim a captured syscall trace of a protocol run.
