# Registry destruction comparison runtime template

This template is not bound to an actual build and has not run either root arm. The generator refuses a missing or unqualified matching build and writes only a fresh local output. Root must review the actual ELF-bound request before its only dispatch.

The same reviewed snapshot root runner supplies 19 unchanged helpers, source and tool revalidation, held-fd execution, exact child wait/kill-on-failure cleanup, fixed 50% CPU and 256 MiB resource checks. Swap usage and the actual swap limit are recorded; an unlimited swap.max is not described as a bounded limit. Main identity is not observed.

Five functions change: qualified_build requires the exact two-arm compilation; root_scope removes the unused role UID account lookup because these controls change no credentials; run_held only adds the arm argument, filenames and exact --expect-* selector; validate_result recognizes the preimage bug and repaired-owner outcomes separately; execute holds and qualifies both artifacts and library closures before either arm, then runs them sequentially. Any first-arm failure prevents the second.

Preimage must actually close every observed Registry-owned descriptor in the foreign shared-VM/shared-files child, and must pass real one-slot EMFILE construction cleanup. This is explicitly a reproduced bug, not preimage qualification. Candidate must retain exact descriptor objects across three owned foreign processes (shared/private fdtable and COW fork), remain operational in the owner, release them on owner destruction, preserve errno and pass partial-initialization cleanup. The reviewed C++ control owns these assertions; the Python reader only verifies its fixed records and complete expected child counts.

No allocator interception, manufactured Registry state, namespace, role service, Android, capability modification, or production source mutation is used. Platform qualification remains false. The future OwnerLease repair and listener work are separate sources and are not included in this Registry comparison.
