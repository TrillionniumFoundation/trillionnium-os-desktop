# BestBuy R2 bounded complete-tree helper

This is a new owned Java-only self-instrumentation package, org.droidloom.qa.bestbuy.r2. It derives from the complete ten-file BestBuy R1 source manifest 1dc5ae021d8b4d3165ac81dd09aef7035651118a9a81380139bdd1caaef668f8, recovered as exact Git UTF8 blobs. The actual R1 readiness run rejected its third inspection at depth 33 with a 32-level limit; 41 attempts and 40 emitted nodes remained an unqualified partial tree. That failure and the first two all-zero public-role observations remain unchanged.

R2 sets a fixed depth ceiling of 128 and uses that same ceiling for both Python path-validation consumers and the Java action-path bound. The recursive walker, complete-tree publication point, password/invisible-content protection, 512-node limit, 64-child limit, 458752-byte tree limit, eight-second helper deadline, twelve-second watchdog and original restoration/failure behavior remain unchanged. Trees that exceed any bound still fail; no prefix or tail qualifies. This limit accommodates the observed 33-level failure, but a future complete Android tree remains unobserved.

The build uses the same seven pinned tools, one CPU, 512 MiB, zero swap, 128 tasks, 230-second inner build deadline and 300-second request timeout. It adds one pure Python production-contract control command after javac; the adapter requires that exact additional command. Sixteen synthetic cases cover deep complete inspections and rejection of partial, oversized, stale-limit and mismatched records. They execute the actual qa_contract parser, not the Android AccessibilityNodeInfo scanner. Java compilation, Python syntax compilation and these controls have not been executed during V8 preparation. Actual execution is required before any build qualification.

The source has a distinct package, protocol, new create-only source/build roots and new signing alias. R1 helper UID 10198 is excluded; no R2 installed UID, APK hash, signer or runtime qualification is invented. Build and staging default to PLAN_ONLY and do not install or interact with Android. Any later readiness run needs the actual R2 build/installation result and a newly reviewed frozen runtime binding. The original Main guard, held transport, Flow and task ownership behavior are not changed by this source build.
