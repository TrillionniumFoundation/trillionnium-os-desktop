Producer04 and producer05 have both completed their unique matching host builds: 121 then 122 supervisor tests, each with 23 relay tests and seven ordinary IPC controls. ## Source change and required host-prefix gate

Producer05 keeps the `pressure_relay: None` command exactly unchanged. For explicit relay policy it selects `/usr/bin/ip netns exec <owned-netns> /usr/bin/unshare` and removes only the unsupported `--forward-signals` argument. Mount, PID, proc, IPC, UTS, fork, kill-child, private propagation, inherited entry executable, and specification arguments remain the same. The exact four-FD ABI, owner pidfd, and init PPid check remain strict.

Before the first namespace test, pin actual `/usr/bin/ip` and `/usr/bin/unshare` contents, executable identity, non-set-ID/non-file-capability status, and bounded `ip -Version`, `unshare --version`, and `unshare --help` output. A historical digest is a comparison input, not a current observation. Confirm the fixed flags against that exact binary. The host test must use the complete prefix; running `unshare` alone cannot answer whether `ip netns exec` closes capabilities or adds a process.

The next host contract is a separate, reviewed, bounded unit. It creates only its one fresh network namespace and private mount/PID/IPC/UTS namespaces, with no veth, NAT, route changes, Android images, Android init, apps, or pressure allocation. A small native probe stands in for the final entry solely to report kernel launch facts. Its test role is explicit; it cannot count as real init constructor or broker qualification.

Required facts are: the actual retained Child becomes the unshare owner; private PID 1 has that exact host PPid; all four fixed FDs refer to the original held objects; the owner pidfd is the same exact Child, with PID 0 in the child's namespace; the endpoint is the original seqpacket pair; the domain test descriptor is the original owned directory; the entry descriptor is the pinned test ELF. Use SCM credentials and a transferred self-pidfd to bind the probe to the actual private process, then independently verify its held proc and namespace identities. Do not substitute a name or PID scan for ownership.

A second fresh prefix attempt tests death propagation. It must prove, with the original pidfds and waits, that loss of the exact owner kills private PID 1 and that loss of the controlling lifecycle process kills its exact outer Child. The tests have separate one-shot attempt IDs and do not re-run an ambiguous prefix. Normal exit and all failures retire the exact unit and network namespace, preserve their receipts, and leave Main unchanged. A failed or incomplete host contract blocks Android admission.

The producer05 matching build includes the pure complete-argv contract. A separate native probe, Python actor and external coordinator now implement the full-prefix control described above, with ordinary local FD/process controls and pure receipt negatives. They have not performed namespace or systemd actions. Their standalone probe is explicitly not the actual Rust Owner or Android init. The first actual prefix execution requires the complete frozen source, matching native build, externally pinned fresh plan and exact Main fence to be reviewed.

The report stores the selected tuple and necessary collision verdicts, not a full account/UID table.

The reservation binds a fresh name, independent attempt nonce, complete absolute stage/data/runtime/evidence paths, all unit names, private sockets, network names, and an exclusive root-owned claim. Every final component is create-only and must be absent before preparation. The parent cgroup must belong to the one newly created canary unit; Main and host-parent controller values are read-only throughout. Unknown launch outcome is reconciled using the same name, nonce and request key; it is never re-dispatched with another key.

Preparation copies only the immutable hash-pinned Android input set into the new stage and creates new data/metadata images with O_EXCL. The init image, bootstrap linker, existing preload, and pre-overlay LMKD service file must all match the explicit policy. No old userdata, APK inventory, signing value or commercial log is copied into publication.

The one candidate daemon is launched with its own socket, supervisor path and spec directory. ## Finite domains and identities

All five domain limits are explicit in the final externally pinned CellSpec: memory.high, memory.max, memory.swap.max=0, cpu.max, and pids.max. They are set before the first Android child joins. Values are not selected from the earlier 384/512 MiB pressure fixture. The a04 daemon's observed peak was 2,841,522,176 bytes under a 4,831,838,208-byte limit; that is planning evidence only. The parent must allocate a separate finite canary budget from current host headroom before this plan is executable. No production budget is inferred.

Within the fresh canary unit, move only the producer/control processes into a host child group. Its empty owned root can delegate controllers to one empty canary cell parent. The producer then creates a fresh `g-<getrandom nonce>` outer envelope and `android` inner domain. Android sees only the inner domain as its cgroup namespace root. The host retains both original directory FDs, device/inode identities and immutable five-limit snapshots. No setting is written to system.slice, the host root, or Main's group. A lack of delegation fails before Android startup.

Bind the exact systemd InvocationID, description nonce, actual daemon/entry/broker binaries, process births, pidfds, and cgroup device/inodes at their first observations. No later numeric discovery can repair a missing original owner. All post-exit counter evidence is sampled while the corresponding group still exists; after removal, use the held-FD deletion proof from R5 rather than reopening a disappeared path or accepting an empty root cgroup.procs alone.

## Real protocol evidence

The Android phase must show the actual pinned `/init second_stage`, its actual bootstrap linker and both expected executable preload mappings. The constructor must send its exact HELLO with kernel root credentials and twelve received FDs; the host must independently verify the held init pidfd/proc, outer Child relationship, ten namespaces, finite domain and image mappings. The generated service file and native LMKD executable must be the actual mounted objects.

Only the real production broker can issue READY. The constructor projects the same held socket inode, echoes PROJECTED, and receives COMMIT after the broker's last readiness check. DONE closes all inherited capabilities before init continues. Actual native LMKD then registers from its own root-verified descendant cgroup, with its expected role, executable and namespace identities. Native threshold/window defaults remain 70/700/1000; no pressure is generated by this init canary. Grant ACTIVE proves enrollment only.

Producer04's ordinary public Status is not a complete protocol audit. Before runtime admission, add or agree a bounded read-only observation surface that retains phase transitions, nonce, immutable budget, exact identities and terminal cause without granting new operations. Missing evidence must stay incomplete. An external canary may not replace HELLO/READY/COMMIT/enrollment proof with source-code inspection, a living daemon, or a successful generic Status reply.

The independent observer must prove capabilities 198–201 are absent after the actual constructor and from later child execs; any observation is bound to retained pidfds/proc directories. It must also verify the post-constructor preload is exactly the pre-existing compatibility preload, with the private opt-in environment removed. If observing an early short-lived fd table is impossible, that gate stays open; a local transport test is not substituted.

## Stop, failure, and persistent claims

Normal Stop goes through the actual candidate daemon. Observe broker retirement with its own joined audit, exact outer Child reap and init death, empty aggregate domains, endpoint/slot removal, owned network teardown, runtime removal, and final generation-marker unlink. Only after those proofs may the new unit retire. The systemd terminal and retained outer group identity must agree with the same invocation. Resource-counter and evidence-write failures cannot skip exact cleanup, and cannot turn the run green.

After daemon loss or an incomplete init handshake, the production marker deliberately remains. Ordinary start/restart/recover must refuse it, including a different runtime path or legacy None. This negative gate can be tested with the same owned identity without starting another cell. A stale marker is not removed by an unconditional unlink, PID lookup, reboot assumption, or a new nonce.

The current implementation has no abandoned-generation recovery API. Therefore the failure arm is not yet admitted as a cleanly recoverable canary. Before inducing loss, either retain an external exact owner for every original process, broker, namespace, domain, endpoint and network object and implement a separately reviewed recovery transaction, or restrict the first actual init attempt to normal Stop and leave destructive failure induction closed. Recovery must compare the original marker inode and bytes, prove no retained or unknown descendant remains, remove only that generation's exact resources, and remove the marker last. An unknown outcome keeps the generation blocked. This is an implementation gap, not a request to weaken the existing gate.
