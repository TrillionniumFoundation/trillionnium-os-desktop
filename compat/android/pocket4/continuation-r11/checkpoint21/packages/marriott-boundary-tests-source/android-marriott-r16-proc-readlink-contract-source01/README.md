# Marriott R16 proc-FD contract candidate

Nine additional ABI tests are provided against the exact historical R16 maps test source. The original three tests are unchanged. This package has not been compiled or executed and contains no device request.

R16's maps open path returns a named memfd, while its readlink adapter redirects only the main executable. The historical Marriott diagnostic records that backing path before the loader fails. The exact source therefore supports a compatibility gap; it does not establish current reproduction or a completed repair.

The production change must reuse the existing authenticated kernel-object provenance client. The supplied factory lifetime02 code creates root-owned sealed snapshots with complete origin tags, but contains no guest client/readlink implementation. That exact existing implementation and source manifest are the remaining source input. This package does not substitute a name-only, integer-FD-only, or permanent-descriptor-registry fix.

The new tests cover absolute and actual-dirfd relative readlink; dup aliases after original close; dup2 replacement; closed-number reuse; close_range on one owned FD; sealed lookalikes under both known names; truncation, no-NUL and EINVAL; closed-FD/bad-dirfd errors; and a PROT_NONE buffer returning EFAULT. Closed-slot reuse allocates with F_DUPFD_CLOEXEC rather than overwriting an unowned number. Every acquired FD is owned and closed through RAII. Actual target headers, syscall support and strict compilation remain unqualified.
