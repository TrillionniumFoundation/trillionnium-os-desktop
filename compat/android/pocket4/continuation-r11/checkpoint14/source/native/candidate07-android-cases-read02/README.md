# Candidate07 actual-bound four-case evidence reader

The actual unique runtime finished and its independently retrieved 30,990-byte original is pinned by SHA256 before any case original is read. This collector rereads only that existing authority file, validates its held/named identity and exact SHA/length, then removes its duplicate text from the transport report. It then reads sixteen fixed originals: the four cases each have durable JSON, durable nonce claim, instrumentation stdout, and instrumentation terminal. Every name derives from the frozen run.py. No directory is enumerated.

The same held root-owned regular-file, nlink1, nonwritable mode, before/after named+FD identity, length, SHA and UTF8 gates apply to every file. Case bounds total 2,228,224 bytes; the separate known authority file has a 4 MiB hard cap. Missing/oversized/changed evidence leaves a FAILED row and makes the reader fail. No bounds expand automatically. Deterministic gzip includes full size and SHA256 of both representations.

The four case names/nonces/packages and required masks were checked against the exact actual runtime result and prepared original in ACTUAL_BINDING.json. This is not yet an independent recomputation of the native signal assertions. The caller must apply the frozen assessor to the original wire/durable/claim/terminal quartet after retrieval. No test is rerun.

Only local default PLAN has run. This source requests sudo solely to read fixed existing root-owned evidence, with 25% CPU, 128 MiB RAM and 30 seconds. It writes no files, creates no children, enters no namespace and changes no Main state. The unbound draft01 was never dispatched or published.
