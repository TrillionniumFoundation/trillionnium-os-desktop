# Audio SDK normal source and updater qualification

The released SDK source-library history correction is already published in parent commit `a291c1fbef3aa0b381109aec9af5dad0112dab09`. This supplement retains that exact `0c93ffaf1bd6fd9f53bbb8463351fadd32429e99d38169d3f13fe042beee25d0` patch and adds only the updater recovery-test isolation change. It does not change production lock behavior, the 430 source-project revisions, the selected SDK inputs, or the source lock `aab71dbce304aba849ac592b5d9cdc2a339cf9208c47faca98f27350c462437d`.

The production lock intentionally survives exec to retain ownership while compiler descendants exist. Running the recovery lifecycle test beside other test threads that spawn processes could accidentally extend its temporary lock lifetime. The test now runs its original assertions in a dedicated child harness. The exact preimage, recovery-only patch and actual tested `main.rs` are included; the replay verifier checks both whole-file hashes. The original normal-test failure remains in the private qualification record.

The actual combined command on desktop was `cargo test --locked --offline -j2 -p droidloom-source -p droidloom-update -- --test-threads=2`. Its outer suites passed 26 source tests, 223 updater tests and two integration tests: 251 tests in total. Nested child harness summaries are not counted again. Two existing opt-in tests remained ignored: the network-fetch source-pin test and the DMA-heap layout test requiring its dedicated AOSP source and host libdrm inputs. No new ignore or skip was introduced. The normal source and updater tools also built successfully. The complete log, command receipts, tool hashes and committed source bindings are included.

The test environment originally lacked `setfattr`, and its EROFS 1.7.1 did not support the required `--workers` option. Qualification used privately extracted Ubuntu attr 2.5.2 and an independently built official EROFS 1.9.4 at commit `f36cadb5c563995ab3aa8572a60ed6b721b9557d`, with LZ4 and multithreading enabled. The unchanged image-repacking metadata assertions passed. Host system packages were not changed.

The completed source-only SDK materializer used recipe `557bff5c84eef7eea9af4533ac7391e3ae676d0f`. The normal-qualified successor recipe is `de1534f4146f3aefc56c6d777545177be62b6029`, through the exact source-history commit `f6c77aa269701c73db99ad38c5245684d1391827`. These recipe roles are distinct and explicitly bound in `SOURCE_HISTORY_READY.json`.

This evidence qualifies the stated normal tests and tools. The independent completed source materialization is recorded under `../source-r2`. This normal-test evidence grants no strict full APEX build, Android boot, application acceptance or production readiness. CI replays the additional patch against its exact preimage; the 251 actual tests are the recorded desktop execution, not a claimed new CI execution.
