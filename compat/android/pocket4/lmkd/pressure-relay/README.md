## The authorization gap and why the stages cannot be combined

The 06a/07b registration and event receipts remain valid observations of their bounded owned fixtures. The old owner authenticates the actual socket process and all of its class metadata, but does not compare that process to a mandatory lifecycle-expected process birth. The 08 real old-library negative proves that another process with the same entire metadata class is accepted. That old owner is therefore **not a production authorization implementation**.

Candidate 08 fixes this concrete authorization gap using a ProcessPin captured independently by trusted lifecycle code. Its positive and negative host controls do not transfer the 07b real event PASS to the new library. A future integrated implementation must qualify the new owner through PSI again, bind the intended guest process from the actual cell lifecycle, pass Android FD-grant integration, and prove its installed supervisor source lineage. No stage changes listener-ancestor ownership requirements or grants access outside the exact cell cgroup.

The earlier r7 trial lost a foreground fixture and remains a hard failure. Candidate b099 remains prohibited for Main. The public adapted event runner lacks the actual private activation authority and predecessor inputs; a summary cannot replace those original bytes.
