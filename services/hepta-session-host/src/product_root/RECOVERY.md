# One explicit original product recovery

`hepta-desktop-root recover --config <Root0600 original input> --operation-id <original operation>`
opens the existing product prefix. It never creates a Fleet, Core home/thread,
issuer, evidence database, empty replay frontier or Notes incarnation as a
substitute for the previous one. The operation ID is only a selector: the
original recovered writer must still verify the exact retained operation,
payload, semantic identity, target and state before the frozen recovery helper
receives a read-only channel. A wrong or unknown selector is an error, never a
new dispatch or successful outcome. The original thread must Resume and compare
its real seed/model/provider/catalog metadata on the final original client.

When every reply was lost, `hepta-desktop-root recover --config <same input>
--latest-original-notes` carries the explicit typed
`latest_recorded_original_notes` selection. It is mutually exclusive with
`--operation-id`. Root retains that selection without opening the cognitive
database or guessing an operation ID. After the canonical writer and original
thread profile have recovered, the original owner resolves a complete bounded
read-only retained cut and verifies the protected original callback identity
before attaching the existing read-only helper. Incomplete records, an
ambiguous latest record, or a legacy record without the original reference
remain unknown. Selection creates no send permission and does not convert a
metadata reference into evidence that the document changed.

The original schema-2 seed must still verify its exact Core configuration and
disabled environment files before any recovery stage is created. Schema-1
seeds do not establish the finite execution profile and are refused, as are
changed file bytes. Recovery never repairs the configuration or creates a new
thread to bypass this refusal.

Only same-boot, clean physical Current is supported. Original typed kernel
retirement observation must prove both the old Agentd and Session gone. A live
predecessor, unavailable birth/boot, live App lock, changed artifacts, missing
consumer/evidence state, Dirty/Publishing/Fenced head or changed independent
material refuses recovery. Root reattaches only the original protected bind
source device/inode. It does not hash a suspect live cognitive database as a
replacement witness. Original Root recovery performs the independent image
verification, installation, Current adoption and custody release.

The original Supervisor loads its actual durable fences and chooses the new
spawn generation. Its driver cannot adopt or signal a disk PID, and cannot
spawn during historical recovery. Only the new explicit FD episode is armed;
a failed spawn consumes it. Stale rendezvous are removed only after real old
owner/Session retirement and original clock ownership, under Root-owned
non-writable ancestors, exact owner/mode/type/inode and ConnectionRefused.
A live socket is refused. Root does not remove the user Session socket: original
Session itself uses its existing exclusive startup lock and live connection
probe. Existing FinalUse snapshot/lock/claim journals must all remain present.

The original issuer key, epoch, local writer lease ID, principal scope, Core
thread/session and old Notes target remain unchanged. The local generation and
owner epoch increase through original rotation and a distinct canonical
successor lease. The new Session Reserved target belongs only to future new
operations. Same-object Root replacement changes exactly the one current Notes
policy slot; the previous operation retains its old target and recovery-only
capability. No policy replacement grants permission to redispatch that old
operation. The new App is not presented as the old editable incarnation.

Initialization requires a 120–300 second original issuer window. Each writer
gets at most 180 seconds, leaving at least 60 seconds inside that original
issuer lease. Recovery waits for actual original writer expiry before rotation;
it never changes a clock, revokes by assumption or renews the original issuer.
The successor receives at most `min(180s, issuer remaining - 60s)`. Expiry stops
writing through the original runtime. No automatic new authority is issued.
A deployment created without a separate writer/issuer window is refused.

This first product entry admits one recovery episode. Root creates
`admin/recovery` once, with write-once public stage observations. Those files are
not an effect ledger or a source of authority: original issuer/registry/Current
and Notes records remain the only authorities. Any existing recovery directory,
including a failure after policy CAS but before sealing/bootstrap, is refused.
A second invocation must not reserve another target or replay an uncertain
step. General partial-ceremony reconciliation and repeated recovery remain
unsupported; preserving these records is necessary for a later exact protocol.

Stage files distinguish admission, stale endpoint retirement, actual original
writer rotation, actual physical Current and bootstrap handoff. They do not
claim that a model ran or an old operation succeeded. Actual acceptance still
requires a current Root-authenticated human turn on the same original thread,
its original status/receipt readback, unchanged old document/receipt identity,
and proof that the prior effect was not repeated. Headless contract/transport
checks, type checks, Root component fixtures and final installed product runs
must be reported separately. This entry does not qualify reboot or power loss.
